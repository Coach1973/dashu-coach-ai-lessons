## 🔧 技術細節（Mac操作前務必先看，能省掉我這邊踩過的坑）

1. **登入狀態per機器**：跟BNI Connect CMS同款限制，Mac要在自己那台電腦的瀏覽器重新登入ezPay（bymyway帳號，大樹教育顧問），不會跨機器同步。
2. **商店選對**：`create_invoice`頁面商店代號下拉選單有兩個選項，`(344031309)大樹教育顧問有限公司`才是這批培訓費發票在用的，不要選`(337643900)大樹教育顧問`。
3. **品項填法（照張騰文那張實際明細反查得出，非猜測）**：品項編號`B03`、品名`BNI培訓`、數量`1`、單位`式`、單價=該員總金額（整筆算，不拆場次）。
4. **🔴🔴 含稅計算最大的坑**：品項列有一個「含稅」checkbox（name=`priceCount`，value=`NET`），**預設不勾＝系統把你填的單價當「未稅價」，會再加5%稅**（親身踩過：填300結果算成315）。**必須用`element.click()`真的點一下勾起來**（不能只改`.checked=true`屬性+dispatch change事件，那樣勾是勾了但金額還是照未稅算，這條跟另一份ezPay SOP的入會/續約發票坑是同一種形狀）。勾對之后填300才會算出稅額14+銷售額286+總計300（含稅300才是教練要的金額）。
5. **數量/單價欄位建議直接用JS填值，不要依賴滑鼠點擊+打字**：第一張發票用`computer`工具triple_click+type完全正常，但第二張開始同樣手法「點擊」完全沒反應（`document.activeElement`還是停在`BODY`，懷疑是含稅checkbox點擊後觸發了DOM重繪，導致座標對不上新版面）。改用JS原生setter設值＋派發`input`+`change`+`keyup`+`blur`四個事件，實測穩定觸發站方計算：
   ```js
   function setVal(el, val) {
     const proto = Object.getPrototypeOf(el);
     const setter = Object.getOwnPropertyDescriptor(proto, 'value').set;
     setter.call(el, val);
     el.dispatchEvent(new Event('input', {bubbles:true}));
     el.dispatchEvent(new Event('change', {bubbles:true}));
     el.dispatchEvent(new KeyboardEvent('keyup', {bubbles:true}));
     el.dispatchEvent(new Event('blur', {bubbles:true}));
   }
   ```
6. **稅額/銷售額/總計欄位查法**：這幾個欄位在`document.getElementById('TotleAmount')`直接查常常抓不到（原因不明，懷疑DOM有動態重建），穩定作法是從`#total_count_table`往下找：
   ```js
   const tds = document.getElementById('total_count_table').querySelectorAll('td:not(.colon_mark)');
   tds.forEach(td => { const inp = td.querySelector('input'); if (inp) console.log(inp.id||inp.name, inp.value); });
   ```
   送出前務必核對`TotleAmount`等於教練要的金額（教訓：另一份ezPay SOP記錄過兩次金額算錯都是含稅沒勾對）。
7. **送出按鈕**：真實id是`create_btn`，是`<input type=button>`不是`<button>`標籤，用`document.getElementById('create_btn').click()`送出，**不要用textContent去找**（input元素沒有textContent，找不到）。
8. **🔴🔴🔴 送出後容易卡住，且必查證**：點下`create_btn`後常常CDP逾時45秒（懷疑是原生確認對話框卡住render thread），操作**所有查詢/送出動作前**先執行`window.alert=function(){}; window.confirm=function(){return true;}`覆蓋掉原生對話框，能預防大部分卡頁。真的卡住時`navigate()`重新載入`search_invoice`頁通常能救回分頁，但**表單清空/分頁恢復不代表發票真的送出成功**——林宜宏那張就是這樣，navigate救回分頁後查證才發現根本沒建立。**每張送出後都必須回`search_invoice`用自訂編號查詢，看到發票號碼+狀態=已開立才算數**，不能只看表單有沒有清空。
9. **查詢頁「查詢項目」下拉選單不能留空**：留空（`SearchItem`值為空字串）送查詢會觸發驗證用的原生alert，一樣會卡頁。查詢時務必先設好`document.querySelector('select[name="SearchItem"]').value = 'CustomNum'`（或其他有效選項）再呼叫`search_invoice_info.send_search_invoice('1')`。
10. **跨機提醒**：Mac操作前務必先`list_connected_browsers`確認連到的是Mac自己的Chrome，不要連錯到這台聯想的瀏覽器（今天稍早BNI Connect那次已經踩過這個坑，見試金石案例60）。
