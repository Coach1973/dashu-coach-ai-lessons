## 2. 整理的規則（教練 2026-09-01 親口確認）

1. **只記約來的來賓**：原始資料裡有寫「🟠來賓/會員」就算一筆，沒寫的不算
2. **寫法不同 = 手動輸入打錯 = 同人**（教練原話：「只是差在字的寫法，唸出來都一樣，就只是寫法不一樣而已」、「哪有那麼巧合同名同姓」）：
   - 三個字完全一樣 → 當然同人
   - 字數一樣 + 字典型讀音一樣 → **同人**（不要假設那麼巧有同名同姓）
   - 教練親口確認的同人範例：
     - 「謝盛峯」「謝盛峯」→ 同人
     - 「連晧宇」「連浩宇」「連皓宇」→ **同人**（唸法一樣）
     - 「楊凱爲」「楊凱為」→ **同人**（異體字，唸法一樣）
     - 「蔡姵彤」「蔡�彤」→ 同人（同音異字）
   - 例外處理：若日後發現真的不是同一人，再拆開
3. **不記缺席、不記遲到、不記代理人**：教練沒交代就不整理
4. **早鳥每週每人只有一項紀錄**：即使原始資料「柯炫任」寫兩次也只算一次（同一週同人只一筆）
5. **來賓會變會員**：早期是某會員邀來的來賓，後來可能自己變成會員，整理時要保留「原始邀約關係」同時標記「現在是否為會員」
6. **「自行出席」**：原始資料出現「�OOO」沒有斜線/邀約會員 = 該會員當天自己到了但沒約人，整理成「約會員 = OOO，來賓數 = 0，備註 = 自行出席」

## 6. 建議 schema（更新版，考慮同人合併 + 來賓轉會員）

```sql
-- 會員主表（用統一寫法，三個字完全一樣才算同人，異體字/打錯字不另開）
CREATE TABLE members (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,         -- 統一寫法（例：「連晧宇」「楊凱為」）
    joined_at TEXT,
    -- 職業等其他欄位暫略
);

-- 來賓出席紀錄（保留歷史來賓，即使後來變會員）
CREATE TABLE meeting_guests (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    meeting_date TEXT NOT NULL,
    inviter_member TEXT NOT NULL,       -- FK → members.name
    guest_name TEXT NOT NULL,           -- 統一寫法後的來賓姓名
    is_self_attend INTEGER DEFAULT 0,   -- 1 = 自行出席
    -- 透過 guest_name JOIN members 可知道現在是不是會員
);

-- 早鳥表（每週同人只一筆，UNIQUE 約束）
CREATE TABLE meeting_earlybirds (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    meeting_date TEXT NOT NULL,
    member_name TEXT NOT NULL,
    UNIQUE(meeting_date, member_name)
);
```
