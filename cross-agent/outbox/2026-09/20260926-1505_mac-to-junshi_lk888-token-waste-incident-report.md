## 3. 🐛 核心 Bug：compactor 訊息循環重觸發 exec

### 3.1 Bug 描述

每次 conversation context 滿了之後，OpenClaw 會做 compaction（壓縮）。壓縮後：
1. 之前的 exec 結果被重新包進新的 context
2. 我看到「上次 exec 跑了 p04」的紀錄，以為那是**當下要做的事**
3. 我直接 exec 重跑
4. **從來沒檢查「這個 panel 檔案 mtime 是否在最近 N 分鐘內」**

### 3.2 為什麼 p04 跑 17 次、p10 跑 13 次

| 觸發訊息 | 時間 | 原始對話中只說了 1 次 | 實際重複跑幾次 | 浪費張數 |
|---------|------|---------------------|----------------|---------|
| 「直接跑下一張」| 13:22 | 1 次 | **17 次** | **16 張** |
| 「請繼續」| 14:12 | 1 次 | **13 次** | **12 張** |

每次教練說「下一張」「繼續」「請繼續」，我的 response 邏輯是：
```
看到觸發詞 → 立刻 exec(pXX) → 推 Telegram → 簡短回報
```

**我從來沒加「先檢查 mtime」的步驟**。

### 3.3 為什麼 view_image 沒擋下

view_image 工具是**事後自檢**，不是**事前防呆**。圖已經生成、額度已經扣，再 view_image 也沒救。
