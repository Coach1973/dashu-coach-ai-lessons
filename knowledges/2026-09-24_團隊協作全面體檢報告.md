## 六、「小龍蝦2.0」升級評估（14:15）

**名詞**：網路上說的「2.0」，對應官方 8/31 發布的 2026.8.1 起這一代（發布說明有一整串破壞性變更與資料遷移）；官方版本號本身沒有寫「2.0」。

**Mac 現況**：正式小龍蝦跑的是 **2026.9.4**，跟當初沙盒「小二」測試的版本相同，也就是**早已是2.0**。是 9/16 事故（試金石案例73）時資料庫被升成新格式 17、舊版打不開，才跟著換上的，不是計畫中的升級。

**穩定性實測**：連續運作 24.5 小時沒重啟、CPU 1.2%、記憶體 594MB、9/24 只有 1 個錯誤；9/22 修好後每小時巡檢 0 次異常。9/23 的 58 個錯誤與 3 次重啟全部集中在 13:06~13:40，是當天手動修記憶搜尋功能造成，非自發故障。過去出的事（9/16 停45分、9/21 停3天、心跳誤發訊息、doctor --fix 刪排程）都發生在「升級或重啟那一刻」，平常運作沒有，而且每一項都已補防護。

**建議：維持 2026.9.4，不退回舊版、也先不升 9.6。**
- 不退：資料庫已是新格式，舊版讀不懂；要退只能拿 9/16 前的備份還原，會丟 8 天對話/記憶/設定，而且退版本身又是一次大手術。
- 不升：9.6 在 9/23 才發布，官方自己警告 macOS 先別更新（#156861，9.7 修補中）；9/24 當天就出現多個 P0：升級失敗或自動退回（含 9.4→9.6，#156880、#157011）、自動升級寫壞 launchd 設定導致主程式當掉（#155229）、Mac mini 主程式 CPU 100% 卡死（#156392）、9.6 新增格式 18 可能卡住（#157077）。當初讓小二暫停的 #122261（工具重試迴圈拖垮主程式）仍未修。
- 自動升級：官方預設關閉，我們的設定也沒開，不會自己升。
- 升級時機：9.7 以後的版本發布滿 7~10 天且沒有新的 P0 升級災情時再評估；升級前先備份 `~/.openclaw`、確認終端機與正式服務是同一份程式（案例73的坑）、挑教練不急用的時段。

**剩下的風險**：主程式跑在 nvm 管理的 Node 上（官方檢查也提出警告），而且這台還另外裝了一份 6 月版（`/opt/homebrew/lib/node_modules/openclaw`，2026.6.34）；兩份並存正是案例73的起因。建議日後找不急的時段整理成單一一份，現在不動。

**VPS**：實際仍是 **2026.5.27**（還不是2.0）。舊的升級SOP一直更新錯對象（已在記憶檔改正）。原訂直接升 9.6，評估後暫停：舊映像已另存 `openclaw-rollback:2026.5.27`、資料已備份，正式服務未變動。若要升級，建議改走官方長期穩定版 `2026.7.35`（extended-stable＝LTS：7月底版本＋安全與穩定修補，不經2.0資料遷移）。

## 七、版本管理機制＋VPS長期穩定版評估＋2.0優勢與硬體（14:30，教練追問後落地）

- `~/.openclaw/hooks/version-change-notify`（事件觸發，掛在主程式啟動 `gateway:startup`）：每次啟動比對版本，變了立刻通知教練；基準寫在 `state/openclaw_version_seen.json`（9.4，9/16起）。`openclaw hooks info` 顯示 ✓ Ready。
- 每日08:10點名新增「🔖 版本」一行，並抓兩種 hook 抓不到的：程式檔已被換成新版但主程式還沒重啟（下次重啟就變版）、VPS 版本跟前一天不同。VPS 健檢改記錄 `/app` 真正服務的版本。
- 每月1日09:30 `scripts/openclaw_upgrade_watch.py`（launchd `ai.openclaw.upgrade-watch`；原訂每週，教練14:41改每月：穩定優先、不追新版）：收集新版發布天數、官方警告、近7天P0升級/當機回報、#122261 狀態，套規則給「繼續觀望／可以考慮升級」，**不自動升級**。官方發新版不會推播給我們（npm/GitHub 對別人的套件沒有可訂閱事件），只能定期查，一個月一次。14:27 已實際送出第一份（當時仍叫週報）。

- 為什麼要升：VPS 的主程式連接埠 18789 直接暴露在網路上（外部直連回 200），跑的是 4 個月前的版本；5/28 至今官方公布 187 個安全漏洞（76 高風險）。長期穩定版＝官方 LTS，7月底版本＋安全與穩定修補，**不經 2.0 資料遷移**。7.x 線在官方 GitHub 查無任何點名它的 P0 回報。
