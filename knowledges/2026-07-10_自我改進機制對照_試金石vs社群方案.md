# 自我改進機制對照：我們的試金石系統 vs 業界方案（2026-07-10）

> 教練提問背景：教練記得上次升級時被提醒「揭露這個技能，資料公開讓大家學習」，要求比較對方值得學的地方，跟我們自己做得好的地方。
> 查證結果：**沒有找到跟這句話完全吻合的過去紀錄**——查了 git log、memory 檔、目前已安裝的 plugin 清單，都沒有「資料強制公開」這件事的紀錄。誠實回報，不臆測。

---

## 一、查證過程（誠實交代，不是敷衍）

1. `git log --grep` 搜「揭露/公開資料/self-improv/telemetry」→ 只找到我們自己內部的 `self-improve(2026-XX-XX)` commit 前綴（是我們自己每晚優化紀錄的命名習慣，不是外部技能）
2. 查已安裝 plugin 清單（`openclaw plugins list`）→ **沒有裝 ClawHub 的「Self-Improving Agent」技能**
3. 查 `openclaw hooks info self-improvement` → 這是 **OpenClaw 官方內建的 hook**（不是 ClawHub 社群技能），描述是「在 agent 啟動時注入自我改進提醒」，本機狀態 `✓ Ready`，是本機運作、沒有看到任何資料外傳的機制
4. WebSearch 查證 ClawHub 那個真正的「Self-Improving Agent」技能實際怎麼運作 → **它的設計反而是「本機優先、預設不分享」**：資料存在 `.learnings/` 資料夾（LEARNINGS.md / ERRORS.md / FEATURE_REQUESTS.md），內建規則明講「絕不記錄密碼/Token/完整原始檔案」，跨 session 分享是**選擇性加入（opt-in），且只分享精簡摘要不分享原始對話**

**結論**：教練記得的那次提醒，我沒能在我們自己的紀錄裡精確定位到，可能是別次升級、別的畫面，或者記憶有些落差——這個我坦白說不確定，不硬湊答案。但比較任務本身照樣做了，因為不管那次提醒具體講了什麼，「自我改進機制怎麼做才好」這個比較本身是有價值的。

## 二、逐項比較：業界方案 vs 我們的試金石系統

| 項目 | 業界 Self-Improving Agent 技能 | 我們的試金石系統 |
|------|------|------|
| 觸發時機 | **明確定義 6 種觸發條件**：指令失敗／教練糾正／要求不存在的功能／外部API失敗／發現知識過時／發現更好做法 | 沒有明確清單，靠當下 AI 自己判斷「這個值得記」 |

| 內容深度 | 精簡摘要、短句 | **完整敘事**：教練原話逐字引用、事件經過、根因分析、悟到什麼、觸發詞、對應守則編號 |

| 學習如何真正落地成行為改變 | 「日後可被 coding agent 處理成修正」，流程沒寫死 | 已有具體案例（今天案例44：簡體字錯誤 → 直接改了 Hook 腳本+既有記憶檔），落地是即時的 |

## 三、值得跟業界學的 2 件事

### 1. 把「什麼時候該記」寫成明確清單，不要靠 AI 臨場判斷

業界那 6 條觸發條件（指令失敗／教練糾正／要求不存在功能／外部API失敗／發現過時知識／發現更好做法）講得很具體。我們現在完全靠當下的 AI「覺得這個值得寫」，不同機器、不同模型（Mac Sonnet／Windows／VPS MiniMax）標準可能不一致，容易漏記。

**建議**：把這 6 條吸收進 `AGENTS.md` 或 `執行細則.md`，變成明確的「該寫試金石的判斷清單」，讓判斷不再看AI心情。

### 2. 把「敏感資料防護」寫成內建規則，不要靠事後抓漏

業界技能是設計時就寫死「絕不記錄密碼」；我們是今天查證密碼分層時**意外**發現 MEMORY.md 裡混進一組真實密碼才補救。這是被動抓漏，不是主動防護。

**建議**：在試金石/distill/memory 寫入的 SOP 裡，明確加一條「寫入前檢查是否含密碼/Token/身分證字號等敏感字串」，變成寫入流程的固定步驟，不是靠事後稽核。

## 四、我們已經做得比業界方案更好、該繼續保持的 3 件事

1. **敘事深度**：業界方案是「幾行摘要」，我們是「完整案例故事」——教練原話、根因、悟到什麼、對應守則。這種深度才能讓不同模型（Sonnet/Opus/MiniMax）真正「懂」規則背後的why，不是只知道規則存在。**不要為了精簡犧牲這個深度。**
2. **跟使命/守則綁定**：業界技能是通用的，換到任何專案都一樣；我們每個案例都扣回特助心法 21 條，這讓試金石不只是「別再犯錯清單」，而是「怎麼實踐使命的活教材」。這是教練 26 年培訓智慧的具體化，業界通用技能複製不了。
3. **跨機共用範圍更廣**：業界技能預設保守（同專案內、opt-in），我們是 Mac/Windows/VPS 全機透過 git 即時共讀同一份試金石案例庫——這對教練「一套系統多台機器」的實際需求更貼合，不需要額外設定。

---

## 五、結論

沒有需要拋棄自己方案、改裝業界技能的理由——我們的試金石系統在深度、使命綁定、跨機範圍上都做得更完整。但兩個具體機制值得吸收：**明確的「該記錄」觸發清單**、**寫入前的敏感資料檢查步驟**。這兩項不影響現有系統運作，是純粹的補強，建議找時間補進 `執行細則.md`。
