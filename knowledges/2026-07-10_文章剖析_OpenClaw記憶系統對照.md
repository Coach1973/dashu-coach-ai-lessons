## 📖 文章核心（一段話總結）

Wisely Chen 認為 **OpenClaw 寧願「每次對話都重讀 Markdown 檔」也不用 RAG**，這不是技術落後，是哲學選擇——為了讓 Agent 有「持續存在」的認知，代價是 Token 燒兇。

四個 Token 粉碎來源：
1. 每次對話讀作業（4-10K tokens 啟動）
2. 記憶檔越來越肥（沒人整理）
3. 心跳背景吃 token
4. 工具輸出無上限

結論：「你付的不是 Token 費，是『持續存在』的成本。」

## 💡 三個可立刻行動的改進點

### 🔥 改進 1：記憶檔大小主動警告機制

**問題**：文章警告「記憶檔越來越肥」。我們 `memory/2026-07-10.md` 已是 17KB / 258 行，本場還早；月底可能破 50KB，越讀越貴。

**做法**：每週日凌晨跑 cron，掃 `memory/*.md`，超過 30KB 主動提醒教練該蒸餾了。

**CP 值**：高（5 分鐘搞定，省未來成本）

### 🔥 改進 3：補一段「cc-switch 為什麼不動」的說明

**現況**：SOUL.md 已寫「小龍蝦不走 cc-switch」，沒寫「為什麼」。
