# SOP：小龍蝦背景研究派工（賈維斯計畫 Phase 4）

> 建立：2026-08-16｜用途：軍師做主版本時，同步讓小龍蝦（main agent，跑MiniMax模型）在背景做「收集型」研究，產出落地成檔案供軍師/教練參考。
> **適用範圍**：收集型任務（找案例、找參考網站、彙整公開資料）。**不適用**判斷型任務（架構決策、寫程式、改資料庫）——判斷永遠留給軍師和教練。

## 派工方式

用 `openclaw cron create` 建一次性任務（非recurring），指定 `--agent main --session isolated`，讓小龍蝦在獨立session背景執行，不佔用教練當下對話。

```bash
openclaw cron create \
  --name "任務簡短標題" \
  --at "+1m" \
  --agent main \
  --session isolated \
  --no-deliver \
  --timeout-seconds 600 \
  --message "見下方『派工單格式』"
```

## 派工單格式（每次派工必須寫死這五件事，否則會拿回一份散文）

1. **要幾個**：明確數字（例：5個網站、3個案例）
2. **記什麼**：每筆固定欄位（例：網址、版面特色、值得抄的三件事）
3. **存哪裡**：明確檔案路徑（`knowledges/研究_主題_日期.md`）
4. **格式範例**：貼一小段範例格式，避免小龍蝦自由發揮
5. **完成後怎麼辦**：通常不用通知教練（軍師會主動去讀），除非教練直接要小龍蝦回報

## 驗收方式

派工單發出後，`ls knowledges/研究_*` 確認檔案產生＋內容符合格式，不是空檔或散文。品質不如軍師親自研究是預期內的（MiniMax模型），重點是「有一份具體材料可以參考」，不是「取代軍師判斷」。
