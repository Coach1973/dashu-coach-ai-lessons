# 模型分工規則：什麼時候請 Opus 出來（2026-09-25 教練親定）

> 教練原話：「重大決策時我會請 Opus 出來，平常一般的庶務類雜事我還是讓 Sonnet 解決。」
> 「如果你覺得需要調動 Opus 出來，就主動提醒我……如果是 Sonnet 就能解決的，就不用提醒我。」
> 「該用 Opus 就用，該省就省。」
> 機制：`scripts/model_tier_advisor.sh`（UserPromptSubmit hook）每句話自動評估並注入提醒。

## 🟣 Opus 級（在 Sonnet 時要提醒教練切換）
符合任一條就是：
1. **找根因**：故障原因不明、修過又復發、已經繞兩輪還沒解決、教練問「為什麼只有X會」
2. **牽涉多個系統**：小龍蝦／赫米斯／網站／VPS／launchd／git 之間互相影響
3. **不可逆或影響大**：刪除、搬遷、架構改動、金鑰安全、花錢
4. **設計機制**：新規則、SOP、防呆 hook、從根源改流程
5. **教練已經不滿**：第二次提同一件事、「浪費時間」「繞一大圈」「又犯」
6. **重要對外內容**：代表教練對外的文案、提案、給別人看的報告

## 🟢 Sonnet 級（不用提醒）
查資料、查名片／發票、照既有 SOP 上架、改文字、小修網頁、開工、收工總結、單一明確指令。

## 提醒怎麼說
- **在 Sonnet 碰到 Opus 級**：回覆只講一句提醒＋一句理由，**先不動手**，讓教練決定：
  「教練，我認為這個任務適合讓 Opus 等級來解決，可能會節省您的時間（理由：…）。要我直接用 Sonnet 做，回『直接做』就好。」
- **在 Opus 碰到庶務**：照常做完，最後一行：「這件是一般庶務，下一件可以切回 Sonnet 省流量。」
- 同一個對話框，同一種提醒只講一次；教練回「直接做」或沒切換，就不再提。
