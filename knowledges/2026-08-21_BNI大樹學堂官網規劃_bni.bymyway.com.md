> 教練原話濃縮：「把我對BNI講過的300多部影片整理成一個教學網站，用來培養更多像佩君老師這樣的超級戰將」

---

## 一、教練的七大優勢 → 網站要承接什麼

| 教練優勢 | 網站該做的事 |
|---|---|
| 1. 會演講 | 影片本身就是最強教材，網站負責「讓人看得完、看得有系統」 |
| 2. 精通組建團隊 | 網站不是單純影音庫，是一套「練成戰將」的訓練路徑 |
| 3. 有海餅乾守則 | 免責聲明+網站調性都要跟海餅乾文化/大樹使命一致，不是冷冰冰的公司教材 |
| 4. 白手起家組團隊的成功經驗 | 內容分類可以呼應「當年怎麼從零開始」這條故事線，給新人信心 |
| 5. 300多部影片 | 核心資產，網站的骨架就是把它們結構化 |
| 6. AI優勢 | 用AI做進度追蹤、測驗出題輔助、排行榜自動計算——這是團隊其他管道做不到的差異化 |
| 7. 個人品牌機會 | 學完的會員未來可以有自己的「戰將主頁」，呼應mentor100模式 |

**教練的要求很明確**：這不是「隨便放影片」，是「逼團隊去讀我的內容，讀完的人會變強」。所以遊戲化機制不是裝飾，是**逼看完+檢驗有沒有真的學到**的機制。

## 三、內容架構與學習路徑設計

300多部影片直接全部上架會變成「一堆影片沒人看得完」，建議做成**闖關式學習路徑**，呼應教練「打造戰將」的敘事：

```
🌱 新手村（BNI基礎觀念、為什麼要做BNI）
    ↓
⚔️ 引薦系統實戰（怎麼給引薦、怎麼收引薦）
    ↓
🎯 1對1與MSP（會員成功專案、深度連結）
    ↓
🎤 分會經營與幹部訓練（CEO/VCP/幹部職務）
    ↓
👑 團隊組建與領導力（大樹教練的組隊心法，最終大魔王關卡）
```

每個關卡（模組）底下放對應的影片，每個模組結束有測驗，過關才能解鎖下一關（或至少顯示「未完成」提醒，不強制卡關，教練可以決定要不要卡關）。

**這條分類軸線需要教練確認或調整**——AI可以先幫忙看YouTube影片標題草擬分類提案，但最終順序、關卡名稱教練最懂。

## 四、遊戲化機制設計

### 1. 學習進度
- 每部影片有「✅ 我看完了」勾選（不做強制影片內嵌行為追蹤，太複雜且YouTube iframe不易精準偵測，用自我勾選+誠信制，符合教練一貫「相信會員」的風格）
- 個人進度頁：顯示「新手村 5/8、引薦系統 3/12...」進度條

### 2. 測驗題
- 每個模組結束3~5題選擇題，測影片核心觀念（不是死記細節）
- 答對即完成模組認證，答錯可重考（不卡人，重點是逼人真的想過一遍）
- 出題來源：AI可先看影片標題/簡介草擬題目，**教練或熟悉內容的人把關正確性**（這塊AI不能自己編，內容是教練的心法，錯了會誤導團隊）

### 3. 排行榜
- 積分公式（可調）：完成影片數 × 10 + 測驗過關數 × 20
- 排行榜顯示暱稱或姓名+分會（**要問教練：真名公開還是給會員選擇匿名，避免有人不想被看到進度落後而卻步**）
- Top 10 榮譽榜，未來可以延伸成「畢業戰將牆」——完成全部關卡的人專屬頁面（呼應教練「個人品牌」的優勢6）

## 五、帳號系統設計

不需要密碼系統這麼重，比照event-signup的手機號碼比對模式即可：
- 註冊：姓名 + 手機號碼 + 所屬分會（不需要email，會員都用LINE/手機習慣）
- 之後用手機號碼當識別碼登入（免密碼，跟教練其他系統操作習慣一致）
- **公開瀏覽影片不需要登入**，只有要「記錄進度/参加排行榜/測驗」才需要註冊——這樣符合教練說的「誰都可以看」但又能追蹤真正認真學的人

## 六、技術架構與部署方式

比照教練現有系統的成功模式（mentor100.bymyway.com / chapters.bymyway.com / rpl-workshop.bymyway.com 都是同一套架構，教練用得順手）：

- **後端**：Python Flask + SQLite（輕量、Mac mini本機部署熟悉、不需要額外主機費用）
- **前端**：伺服器端渲染模板（跟其他姊妹站一致風格），影片用YouTube iframe直接嵌入（不下載影片、版權留在YouTube、不佔硬碟空間）
- **網域**：`bni.bymyway.com`，走Cloudflare DNS A紀錄 → Mac mini反向代理（跟`go.bymyway.com`、`chapters.bymyway.com`同一套已驗證過的流程）
- **部署位置**：Mac mini本機（跟其他姊妹站同一台機器同一套模式）

**⚠️ 重要提醒**：我現在是雲端遠端的Claude Code session，**摸不到Mac mini本機、也碰不到Cloudflare DNS設定**。我可以在這裡把程式碼骨架、資料庫schema、頁面模板都先寫好、commit上雲端，但**最後的DNS設定+服務啟動+反向代理，要回到Mac桌面版或終端機那邊才能完成**（跟其他姊妹站建站時是同一個交接模式，不是新問題）。

## 七、資料模型草案

```
members       (id, name, phone, chapter, created_at)
modules       (id, name, order_index, description, unlock_after_module_id)
videos        (id, module_id, youtube_id, title, order_index)
video_progress(member_id, video_id, completed_at)
quiz_questions(id, module_id, question, option_a/b/c/d, correct_option)
quiz_attempts (id, member_id, module_id, score, passed, attempted_at)
```

排行榜、進度百分比都是從上面幾張表即時算出來，不需要額外存一張「積分表」（避免資料不同步）。

## 八、分階段執行計畫

**Phase 1（MVP，建議先做這階段驗證流程）**
- 網站骨架：首頁 + 免責聲明 + 註冊/登入(手機比對) + 一個示範模組
- 教練先挑10~20部代表性影片試跑（不用一次處理300部）
- 基本測驗（每模組3題）+ 進度條 + 排行榜
- 教練跟身邊1、2位會員（例如佩君老師）先試用，抓體驗問題

**Phase 2（內容擴充）**
- 教練提供完整300部影片清單（最理想是YouTube播放清單連結，可以整批匯入，省去一支一支貼的功夫）
- 依內容分類擴充成完整的5個關卡模組
- 測驗題庫擴充到每模組都有

**Phase 3（進階功能）**
- 「畢業戰將牆」個人品牌頁（呼應教練優勢7）
- 積分制度優化、可能加入教練想要的獎勵機制
- 視教練需求決定要不要串LINE推播（如「恭喜完成新手村」）

## 九、需要教練決定/提供的事項（不確定的先問，不用猜）

1. **300部影片在哪裡？** 有沒有整理成YouTube播放清單？還是散落在頻道各處要重新蒐集連結？
2. **先做全量還是先做MVP試跑？** 建議先挑10~20部代表性影片驗證整套流程再擴充，教練同意嗎？
3. **五大關卡的分類/命名教練認可嗎？** 我先照BNI一般培訓邏輯草擬，教練最懂哪些影片該放哪一關
4. **測驗題誰出？** AI可以先草擬，但正確性要教練或熟悉內容的人把關，教練是要自己出，還是要AI先生出草稿讓教練審？
5. **排行榜要不要真名公開？** 還是給會員自己選顯示暱稱
6. **要不要卡關（沒過測驗不能看下一關）？** 還是純鼓勵性質不強制
