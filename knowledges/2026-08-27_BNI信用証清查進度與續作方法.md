## 續作SOP（下一棒照這個流程做，不用重新摸索）

### 1. 開瀏覽器、選裝置
用`mcp__claude-in-chrome__list_connected_browsers`確認，用`select_browser`選**本機Mac的deviceId**（isLocal:true那台）。教練指定過只用本機這台，不要問，除非又出現新裝置。

### 2. 每個memberId的查詢流程（一個JS腳本搞定判斷）
對每個memberId：
```
navigate → https://www.bniconnectglobal.com/web/secure/operationsRegionEditMembership?legacyPortal=true&memberId={ID}#tabs-6
wait 1.2秒
javascript_exec:
const links=Array.from(document.querySelectorAll('a'));
const c=links.find(x=>x.textContent.trim()==='信用證');
const g=links.find(x=>x.textContent.trim()==='產生信用證');
if(c){const href=c.getAttribute('href'); if(href&&href.includes('memberCertificateOfCreditId')){location.href=href;'ISSUED_NAV'}else{'ISSUED_EXPIRED'}} else if(g){'NOT_ISSUED'} else {'INELIGIBLE'}
wait 1.2秒
get_page_text  ← 這時如果是ISSUED_NAV，畫面已經跳到信用證明細頁，裡面有：編號/會員/公司/信用額度/會員資格結束日期/發行日期/發行人/可執行的(轉移會員資格/已贖回/轉移月數等)/轉移給/轉移日期
```

**四種結果判讀**：
- `ISSUED_NAV` + get_page_text顯示信用證明細頁 → cert_status=issued，記錄cert_id(編號)/issue_date(發行日期)。看「可執行的」欄位：沒有出現=usage_status='active'（仍有效，教練最關心這種）；出現「已贖回」或「轉移給XXX(自己名字)」=usage_status='redeemed'；出現「轉移給XXX(別人)」=usage_status='transferred'，記transferred_to+transfer_date。
- `ISSUED_EXPIRED` + get_page_text還是tabs-6頁面（沒跳轉）→ cert_status=issued, usage_status='expired'（href="#"代表已過期，不用再點進去確認，這是已驗證過的規則，coach親口確認過）
- `NOT_ISSUED` → cert_status='not_issued'，這是「未開立」名單，教練要的是離會日期（會員資格到期日欄位，但那是原定到期日不是實際離會日；若要精確離會日要另外查tabs-8會員資格歷史的「終止會員資格」事件，時間不夠可以先用會員資格到期日代替，備註說明）
- `INELIGIBLE` → cert_status='ineligible'，沒有信用証相關選項，因為沒有剩餘會期可以開立，這種不算未開立也不算已開立，是第三類，仍要記錄但教練的兩份清單都不需要列入

### 3. 批次操作建議
一次browser_batch放5個member的查詢（每個member= navigate+wait+jsexec+wait+get_page_text共5個action，5個member=25個action），這是實測過穩定的節奏，不要貪心塞更多否則單次輸出會太長難以核對。

## 血淚教訓（下一棒必看，避免重踩）
1. **BNI Connect的離會會員清單URL不能只靠URL帶chapterId參數**——伺服器認的是session狀態，必須先在`operationsHome#adminactiontabcontentstructurechapter`頁面真的點擊該分會的連結（`document.querySelector('a[name="{chapterId}"]').click()`），等1.5秒，session才會真的切換，之後navigate到`operationsChapterManageMembership`才會抓到正確分會的資料，不然會一直抓到上一個分會的舊資料而不自知（真鑫誤判成真鑽的血淚）。
2. **搜尋表單的送出按鈕(`#searchMembers`)用電腦真實click常常無效**（沒有觸發AJAX），要改用`window.jQuery('#searchMembers').trigger('click')`才可靠，狀態下拉選單也要用`window.jQuery(select).trigger('change')`才會被表單邏輯讀到。
3. **DataTables是純client端渲染**（bServerSide:false），可以直接用`window.jQuery('#datalist').dataTable().fnGetData()`一次拿到全部資料（不受分頁限制），不用一頁一頁翻，這是抓「離會會員名單+memberId」最快的方法。
4. **javascript_exec回傳值如果是物件(`{...}`)或包含cookie/query-string形狀的字串常會被安全過濾器整包擋掉變成`{}`**，要回傳單純字串（用字串拼接、不要`JSON.stringify`一個物件），且避免在字串裡出現看起來像URL query string的內容。
5. **memberId對應「編輯資料」頁的直連URL是**：`https://www.bniconnectglobal.com/web/secure/operationsRegionEditMembership?legacyPortal=true&memberId={ID}#tabs-6`——這是唯一能穩定拿到「會員資格詳細資料」(含信用証狀態)的路徑，不能用`fetch()`直接打這個URL（會拿到不含這段內容的殘缺HTML，原因不明，猜測是該區塊由額外client端邏輯根據session/日期動態渲染，只有真實瀏覽器navigate才拿得到），必須用真實navigate。
6. **信用証明細頁**是`https://www.bniconnectglobal.com/web/secure/viewAdminRegionCertificateOfCredit?isFormSubmit=true&memberCertificateOfCreditId={certId}`，可以從tabs-6頁面的「信用證」連結的href直接抓到certId後用`location.href=href`跳轉，不需要真的用滑鼠點擊（`location.href=href`比`computer left_click`更穩定、更快）。

## 教練確認過的重要邏輯釐清
- 「信用証是否過期」看的是**發行日期+2年**，不是離會日期+2年——這兩個日期常常差很久（教練親口糾正過這點，不能用離會日期當捷徑判斷過期）
- 還沒開立(NOT_ISSUED)的人**沒有過期問題**，因為根本沒發行過任何東西，會一直停留在「可以隨時被開立」的狀態
