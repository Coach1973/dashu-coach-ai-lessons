## 🔧 自動化五個具體步驟

### 第一步：建立「任務前自動鉤子腳本」

**問題**：我需要手動去讀 trigger_index.md

**具體做法**：
1. 建立 `~/.openclaw/workspace/scripts/pre_task_hook.sh`
2. 這個腳本在每次收到任務時自動運行
3. 根據任務關鍵字自動調取相關守則
4. 把相關守則顯示給我看

**範例**：
```
用戶說：「幫我上傳到 GitHub」
↓
pre_task_hook.sh 自動偵測關鍵字「GitHub」「上傳」
↓
自動調取守則 #04：「解決問題比解釋問題更重要」
↓
自動顯示：「交付前先用 curl 檢測 HTTP 狀態碼」
```

---

### 第二步：建立「犯錯自動蒸餾」流程

**問題**：犯錯後需要手動寫入 HEARTBEAT.md，再手動蒸餾進 handbook

**具體做法**：
1. 建立 `~/.openclaw/workspace/scripts/mistake_detector.py`
2. 當 commit message 包含「fix」「bug」「錯誤」等關鍵字
3. 自動分析失敗原因
4. 自動更新 trigger_index.md
5. 自動更新 failure-case-handbook.md

**範例**：
```
我 commit：「fix: 404 error」
↓
mistake_detector.py 自動偵測
↓
自動寫入：「觸發條件：deploy 後沒檢測 → 新增行動：先 curl 檢測 200」
↓
自動更新 trigger_index.md
```

---

### 第三步：在 CLAUDE.md 加入「自動對照」指令

**問題**：CLAUDE.md 說「讀取守則」，但沒有說「自動對照」

**具體做法**：
在 CLAUDE.md 中加入：

```markdown
## 🔄 任務前自動鉤子

當收到任務時，系統自動執行：
1. 讀取 ~/.openclaw/workspace/knowledges/01_knowledge_base/trigger_index.md
2. 根據任務關鍵字，找出相關觸發
3. 在回覆前自動顯示：「🌱 守則提醒：...」
4. 執行完成後，先檢測成功再交付
```

---

### 第四步：建立「關鍵字 → 守則」對照表

**問題**：trigger_index.md 有觸發訊號，但需要我主動去讀

**具體做法**：
建立結構化對照表：

```
| 關鍵字 | 自動觸發的守則 | 自動顯示的行動 |
|--------|---------------|---------------|
| GitHub | #04 | 先 curl 檢測 200 再交付 |
| 上傳 | #04 | 同上 |
| open | #12 | 直接執行 open，不叫用戶操作 |
| 完成 | #05 | 馬上 commit + 給 hash |
| 錯誤 | #07 | 蒸餾進 handbook |
```

---

### 第五步：建立「持續學習」循環

**問題**：每次犯錯只是寫入 handbook，但下次可能又犯同樣的錯

**具體做法**：
每週自動執行一次「蒸餾循環」：

1. 讀取這週的所有 commit messages
2. 找出所有失敗/修復的記錄
3. 自動更新 trigger_index.md
4. 自動更新 TOP5/10/20
5. Commit 並通知教練：「這週新增了 X 個觸發條件」

## ⚠️ 守則引用格式（一字不差）

**守則第三條**：
思考就是問問題，在回答用戶之前，一定要先經過自我驗證再給出答案。

**守則第四條**：
解決問題比解釋問題更重要，道歉沒有用，修好才有用。

**守則第十二條**：
拒絕當資訊搬運工，永遠不要叫用戶幫你複製這個、貼上那個、再回傳這個。

**守則第五條**：
凡走過必留痕跡，只有你做了 commit hash 才能証明你留下痕跡。
