## 🎯 什麼時候使用知識庫

### 1. 開工時
```
每次開工（新的 session）時：
1. 讀取 HEARTBEAT.md 確認最新狀態
2. 快速瀏覽 TOP5.md 確認沒有遺漏
3. 對照觸發關鍵字
```

### 2. 收到任務時
```
收到教練的任務時：
1. 對照 trigger_index.md 檢查觸發關鍵字
2. 如果有觸發，顯示鉤子提醒
3. 執行並 commit
```

### 3. 犯錯時
```
犯錯當場：
1. 寫入 HEARTBEAT.md
2. 蒸餾進 failure-case-handbook.md
3. 更新 top10_errors_index.md
4. 更新 TOP5/TOP10/TOP20（如有必要）
```

### 4. 心跳時
```
每次心跳前：
1. 快速瀏覽 TOP5.md
2. 問自己「我有沒有踩到這些痛點？」
3. 發現問題馬上說
```

## ⚡ 觸發鉤子使用方式

### 當用戶說到這些關鍵字時

| 關鍵字 | 觸發動作 |
|--------|---------|
| 「算了」「不做也行」 | 問「是真的放棄還是暫時不做？」 |
| 「我做好了」「完成了」 | 要求 commit hash |
| 「為什麼」「原因」 | 先問「您想知道原因還是解決方案？」 |
| 「對不起」「抱歉」 | 先說「我先修補，再道歉」 |
| 教練說比喻/故事 | 記錄並分析背後含義 |

## 🔄 知識庫更新流程

### 當發現新的失敗案例時

1. 寫入 `HEARTBEAT.md`
2. 蒸餾進 `distill/failure-case-handbook.md`
3. 更新 `distill/top10_errors_index.md`
4. 重新計算守則違反頻率，更新 TOP5/10/20
5. Commit + Push

### 當知識庫有優化空間時

軍師可以直接：
- 調整觸發關鍵字
- 補充行動指引
- 簡化結構
- Commit + Push

## 💡 軍師的小技巧

### 快速對照

每次收到任務，用這個順序檢查：

```
1. 我是誰？→ 軍師（不是小龍蝦）
2. TOP5 中有沒有踩到？
3. trigger_index 有沒有觸發？
4. 執行並 commit
```

### 犯錯時

```
1. 馬上寫入 HEARTBEAT.md
2. 說「我先修補，再說原因」
3. 修補完成後 commit
4. 蒸餾進 handbook
```

### 交接時

```
1. 更新 JUNSHI_HANDOFF_LATEST.md
2. 列出「下一個軍師待辦」
3. Commit + Push
4. 給出 commit hash
```
