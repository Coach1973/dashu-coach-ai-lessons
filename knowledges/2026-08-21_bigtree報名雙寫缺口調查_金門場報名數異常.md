# bigtree-tw報名雙寫缺口調查：金門場(8/21)報名數異常

> 建立時間：2026-08-21
> 建立者：Claude Code Remote（雲端遠端session）
> 觸發原因：教練反映「金門當地推廣人員說報名十幾個，但今天請小龍蝦統計官方LINE訊息只有5個」

---

## 一、查證過程

1. `event-signup/app.py`確認`/api/register`端點（第290行起）**確實存在且邏輯正常**：接收`slug`/`name`/`phone`等JSON，比對`events`表找到對應場次後寫入`signups`，並推播`_notify_coach_line()`。註解寫明是2026-08-14教練裁示「報名資料要落地在bymyway.com自己的資料庫，不能只活在LINE/Telegram通知訊息裡」而建的。

2. 查`bigtree`repo的`index.html`（教練官網主站的報名表單`submitRegistration()`函式，約611行起），發現送出報名時**只打了兩支API**：
   ```js
   const REGISTER_API = 'https://sme-register-fn.netlify.app/.netlify/functions/register'; // 純轉發，不落地任何資料庫
   const NOTIFY_API = 'https://xiaolongxia-notify.netlify.app/.netlify/functions/notify';   // 純推播佩佩老師，不落地
   ```
   **完全沒有**呼叫`/api/register`。

3. 用`grep -rn "api/register\|bymyway.com/api"`+`grep -n "slug"`掃過整個bigtree repo（含所有分支歷史`git log --oneline -- index.html`），**一次都沒出現過**。代表這不是「有寫但被之後的改動蓋掉」，是**從頭到尾沒寫過**。

4. 確認bigtree-tw的Netlify部署方式是`git archive --format=zip -o x.zip HEAD`直接從git repo打包（`claude-brain/feedback_netlify_headers_content_type.md`第46行有記錄這個機制），代表**部署站點的程式碼跟git repo內容必定一致**，不存在「線上有改但沒commit回git」的可能性——bigtree-tw正式站現在跑的`submitRegistration()`就是我看到的這個版本。

## 二、結論

- **全部場次**（不只金門場）的報名，從bigtree-tw這個主要入口送出時，**從來沒有一筆真正寫進任何資料庫**。
- 唯二會發生的事：①`sme-register-fn`把報名內容轉發到教練LINE（純訊息，不查詢、不去重、不存檔）②`xiaolongxia-notify`把同樣內容推給佩佩老師LINE（一樣不存檔）。
- 如果有人想「事後統計某場報名了幾個」，唯一能查的地方就是**教練LINE裡那些通知訊息本身**——這正是小龍蝦這次做的事：去掃LINE訊息數「5」。
- 金門推廣人員說的十幾個，如果是透過**別的管道**（口頭、當地群組、電話）收單，從來沒有經過網站表單，那**這幾筆報名資料完全不存在於任何系統裡**——不是bug漏接，是這些人本來就沒有機會被系統看見。
- 舊接力棒記錄（`JUNSHI_HANDOFF_LATEST.md`裡「報名系統雙寫遷移bymyway.com」那一列）寫「已建`/api/register`端點+15場session slug+bigtree前端雙寫，deploy已上線」——**後半段「bigtree前端雙寫」這句話是不實記錄**，可能是當時規劃完成但實際程式碼從未真的寫上去、或寫在別的地方後來遺失，目前已查無法還原當時發生了什麼，只能確認**現狀是沒有**。

## 三、下一步：把雙寫真正接上去（防止未來場次再發生同樣的事）

### 需要的資訊（雲端session這裡拿不到，需要Mac或有event.db存取權限的人跑一次）

```bash
cd ~/.openclaw/workspace/event-signup
./venv/bin/python3 -c "
import db
conn = db.get_conn()
rows = conn.execute('SELECT slug, name, event_date FROM events ORDER BY event_date').fetchall()
for r in rows:
    print(r['slug'], '|', r['name'], '|', r['event_date'])
conn.close()
"
```
把輸出貼回來（或存成檔案讓下一棒讀），就能知道每場活動在資料庫裡登記的真實`slug`是什麼。

### 已經想好的修復方式（等slug清單到位就能立刻寫）

在`bigtree/index.html`的`submitRegistration()`裡，`REGISTER_API`/`NOTIFY_API`那兩個`fetch`旁邊，多加一個：
```js
const BYMYWAY_API = 'https://event.bymyway.com/api/register';
// 需要一個 "顯示用場次文字" → "event.db真實slug" 的對照表，例如：
const SESSION_SLUG_MAP = {
  '8/21（五）夜｜金門場': '0821-jinmen',   // ← 實際slug要換成event.db查出來的真實值
  '8/22（六）下午｜金門場': '0822-jinmen', // ← 同上
  // ...其餘場次
};
const slug = SESSION_SLUG_MAP[session] || '';
if (slug) {
  fetch(BYMYWAY_API, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ slug, name, phone, company: '', email: '' })
  }).catch(() => {});
}
```
**為什麼沒有直接猜slug先寫上去**：`/api/register`對查無對應slug的請求，會回傳`{"ok": false, "error": "unknown slug"}`但HTTP狀態碼仍是200——畫面上使用者完全看不出失敗，等於猜錯了會靜默失敗、又製造一次跟這次一樣「以為有存但其實沒存」的狀況。寧可先確認真實slug再一次寫對，不要用「反正之後可以再查」的心態賭一次。

### 這次金門場已經流失的報名，能不能補救

不能技術性復原（資料本來就沒進系統），但可以請教練或當地推廣人員把口頭/其他管道收到的名單直接告訴任何一台機器，用`event-signup`的`/admin`後台手動新增（或請教練直接告知名字電話，由AI用`db.upsert_signup()`補登），至少讓這場活動的簽到/集點功能能認得這些人。
