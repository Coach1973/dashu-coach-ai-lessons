# 自動蒸餾 SOP（教練 2026-07-10 糾正後定稿）

> 起源：教練發現我把「記憶檔過大」處理設計成「通知教練去處理」
> 教練原話：「不超過 30 KB，你就自動蒸餾就好了，幹嘛還要提醒我？是沒事給我找事情做吧？」
> 建立時間：2026-07-10 08:27 台灣時間
> 設計者：🦞 小龍蝦學長

---

## 🔴 教訓（本場最關鍵）

### 守則 #08 應用：「花時間討論就是為了執行」

**我原本的錯誤設計**：cron 跑完通知教練「要不要蒸餾？」→ 把責任推回教練
**教練要的是**：cron 跑完就蒸餾完，**不要來煩**

### 守則 #11 應用：「自動自發要體現在每次的主動關懷」

**錯誤理解**：主動 = 主動提醒
**正確理解**：主動 = **主動做完**，不是「主動丟問題給你」

### 守則 #12 應用：「拒絕當資訊搬運工」

**錯誤理解**：通知教練 = 給他資訊
**正確理解**：把 AI 能做的事（蒸餾）推給教練 = **搬運工變相版**

## ✅ 自動蒸餾 cron 設計定稿

| 欄位 | 設定 |
|------|------|
| Cron ID | （建好後回填）|
| 觸發時間 | 每週日早上 8:00（Asia/Taipei）|
| 觸發條件 | `~/.openclaw/workspace/memory/*.md` 任一檔案 > 30KB |
| 動作 | **自動** LLM 蒸餾到 MEMORY.md + 原始檔歸檔到 `memory/archive/` |
| 通知 | **完成後簡短回報**（不是「請求許可」），全部正常時靜默 |
| Session | isolated（不擾教練主對話） |
| 日誌 | `logs/memory_distill_weekly.log` |

## 📦 蒸餾流程（cron 內 agentTurn 完整步驟）

1. 掃描 `~/.openclaw/workspace/memory/*.md`，找出 > 30720 bytes（30KB）
2. 若全部都 < 30KB → **靜默結束**（不通知教練）
3. 對每個過大檔案：
   - 讀取完整內容
   - LLM 提取精華（決策、教訓、待辦、人物、commit hash、教練口述關鍵字）
   - 增量 append 到 `MEMORY.md` 的 `## Promoted From Short-Term Memory (YYYY-MM-DD)` 段落
   - 保留 `<!-- openclaw-memory-promotion:memory:memory/YYYY-MM-DD.md:行號:行號 -->` 標註格式
   - 原始檔歸檔到 `memory/archive/YYYY-MM-DD.md`（mkdir -p archive）
   - 原始檔本身 **保留前 200 行 + 加註**「[已蒸餾歸檔，完整內容見 memory/archive/YYYY-MM-DD.md]」（避免無窮迴圈）
4. 完成後 Telegram 簡短回報（不是問問題）：
   ```
   🦞 教練，本週自動蒸餾完成：
   - 處理了 X 個檔案：memory/2026-07-XX.md（XX KB）、...
   - MEMORY.md 增量 +XXXX 字
   - 原始檔已歸檔到 memory/archive/
   - 不需要您做任何事。
   ```
5. 記錄到 `logs/memory_distill_weekly.log`

## 🎯 未來的我注意

- **AI 能做的事，別叫教練做**（守則 #12）
- **完成才回報，沒事別通知**（守則 #11）
- **通知 ≠ 請求許可**（守則 #08）

如果未來我又在設計「通知教練去處理 X」型方案 → 停下來，先問自己：
「這個 X AI 能不能直接做？」如果能 → 改成「AI 自動做 + 簡短回報」。
