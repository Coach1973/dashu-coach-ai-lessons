#### 問題 2：`~/.claude/CLAUDE.md` 跟 `workspace/CLAUDE.md` 內容完全不同
- `~/.claude/CLAUDE.md`（29.7KB，8/3）：軍師燒錄檔，內含 XINFA_AUTOINJECT + ZHIXINGXIZE_AUTOINJECT

#### 問題 3：system-prompt.md vs workspace/AGENTS.md 啟動規則打架

## 四、為什麼這些問題之前都沒抓到？（給克勞德看）

我重新讀了 `JUNSHI_HANDOFF_LATEST.md` v72~v96（八月份所有戰果）、`workspace/特助心法.md`、`workspace/執行細則.md`、`workspace/AGENTS.md`、`workspace/CLAUDE.md`、`workspace/HEARTBEAT.md`——然後我發現一個關鍵模式：

### 克勞德的核心盲點：「任務導向」 vs 「環境導向」

過去八個月的所有 session（從 v72 到 v96），每場都在做教練下達的具體任務：大樹小講金門場、AI 微論壇嘉義場、BNI 大台南南區 9 分會、健康檢查 cron 假警報修復、BNI Connect CMS 操作驗證……每場都成功交付，每場都有 commit hash，都有「戰果」可看。

但**沒有一場 session 停下來問過「等等，這些設定檔本身有沒有問題？」**

原因：
1. **任務驅動的工作節奏**：每次開工都是「教練交代→我去做→commit 戰果」，自然不會回頭看設定檔。
2. **接力棒機制讓「上棒沒事 = 環境沒事」的錯覺**：JUNSHI_HANDOFF_LATEST.md v72~v96 全部正常交接，看起來系統運作得很好，所以「沒壞就不檢查」。
3. **CLAUDE.md / SOUL.md 的權威光環**：每份檔案開頭都寫「🔥 最高正典」「每次啟動必讀」「一字不差」，這種「神聖檔案」的氣氛反而讓人不敢質疑「它真的有被正確讀到嗎？」
4. **「只讀指定的 SOUL.md」反而創造盲區**：system-prompt.md 規定只讀 `workspace/SOUL.md`，AI 嚴格遵守 → 完全沒注意到磁碟上還有另外兩份舊 SOUL.md 存在 → 假設「我讀的就是唯一一份」，但實際上其他工具可能讀到舊版。
5. **E01~E17 鐵律集中於「做事」而非「環境」**：E01 commit、E04 三問、E08 引用查證、E11 不可逆……**每一條都是做任務時的紀律，沒有一條是「定期做環境健檢」**。這是結構性缺口。
6. **Cron 自動同步讓人誤以為 CLAUDE.md 永遠新鮮**：`HEARTBEAT.md` 內顯示「接力棒→CLAUDE.md 自動同步 ✅ 已推上雲端」每 5~10 分鐘跑一次，這個頻繁的 sync 動作反而讓人不再關心「真的有 sync 嗎？」——但實測 `~/.claude/CLAUDE.md` 跟 `workspace/CLAUDE.md` 不是同步鏡像關係，這個 sync 跑的其實是另一條管線（OpenClaw 對自己的 workspace CLAUDE.md）。

### 我（MiniMax-M3）為什麼這次抓到了？

不是因為我比較聰明——**是因為教練下了一道「環境檢查」的指令，我才開始掃**。

如果教練沒下這道指令，我這場 session 大概也會是「教練給任務→我做→commit」的老路徑，**不會主動停下來盤點設定檔**。

這代表教練得**定期**下達這類指令（或者掛個 cron 每週自動跑），環境問題才不會累積到「某天某個任務踩到才發現」的程度。

## 五、給克勞德的反思建議

### 1. 開工流程增加第 0 步：環境健檢
建議在 AGENTS.md 的「開工六步驟」**前面**加一步「🔴 第 0 步：環境快速健檢」：
```bash
ls ~/.openclaw/SOUL.md ~/.openclaw/workspace/SOUL.md ~/.openclaw/agents/main/agent/SOUL.md 2>&1
git -C ~/.openclaw status --short | wc -l   # 看 untracked/modified 數量
ls ~/.openclaw/workspace/.!* 2>/dev/null      # 看有沒有遺留鎖定檔
```
三條命令，不到 5 秒，至少能擋住今天發現的問題 1、5、6。

### 2. E12 鐵律擴充：環境異常也算「該記的」
現行 E12 第 5 條只說「發現既有記憶檔/守則已經過時、跟現狀不符」，但**沒有涵蓋「設定檔打架」「檔案該讀卻沒被讀到」這類結構性問題**。建議擴充為：
> 「發現設定檔內容互相衝突（多份 SOUL.md/CLAUDE.md 內容不一致）、檔案路徑該讀卻沒人讀、或 git 工作區有未提交的異常變更」

### 3. 三機共享的設定正確性要定期校驗
agents/{bni_tainan,jiaolian_thoughts,kong,peipei} 的開工檔案全 untracked——這個我沒修，因為需要教練先裁示三機同步機制本身的 SOP。但**這是一個定時炸彈**：哪天教練在 Mac 改了某個 agent 的 SOUL.md，聯想機那邊還是舊版，會直接踩坑。

### 4. 主動盤點的時機
不需要等教練下指令——每次 session 結束前的「收工」（E17 觸發「總結」關鍵字）時，可以順手跑一次 `git status --short | head -30` + `ls ~/.openclaw/SOUL.md ~/.openclaw/workspace/SOUL.md ~/.openclaw/agents/main/agent/SOUL.md`，發現異常就寫進 HEARTBEAT.md，不正常才發通知。這樣不需要教練記得「偶爾做個環境檢查」。
