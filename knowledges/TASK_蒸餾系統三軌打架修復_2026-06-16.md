## 📋 背景

教練 2026-06-16 下午 4:04 和晚上 8:04 在 Telegram 收到「pending_distill 空空如也，今日無待蒸餾對話」訊息。教練覺得不對——明明早上就跟軍師工作半天。

軍師 Opus 4.7（本場）調查發現：

**系統裡有三套蒸餾系統同時運作，互相打架**：

| 系統 | 建立日期 | 狀態 | 觸發 |
|------|---------|------|------|
| **A. 舊系統（活著）** | 2026-06-03 by 軍師 | ✅ 運作中 | 系統 crontab：`*/15` 備份、`*/30` 蒸餾 |
| **B. 中午橋接層** | 2026-06-16 12:21 軍師 Opus 4.7 | ⚠️ 已部署但無用 | macOS launchd `com.bymyway.sync-jsonl-distill`（每 4 小時 :55）|
| **C. 新 cron（推進度）** | 2026-06-16 凌晨 c4719f4 | ❌ 永遠看到空 | OpenClaw cron「終端機對話全自動蒸餾（每4小時）」`0 */4 * * *` |

### 為什麼 C 永遠看到空？

A 系統的 `backup_terminal_sessions.sh` 每 15 分鐘把 `~/.claude/projects/-Users-bymyway--openclaw/*.jsonl` 拷到 `terminal-notes/raw_sessions/`，然後 `run_terminal_distill.sh` 每 30 分鐘讀 raw_sessions、蒸餾、寫進 `distilled/`、git push。

但 C 系統的 cron prompt 寫的是「看 `terminal-notes/pending_distill/` 有沒有 .txt」——這個資料夾**永遠空**（A 系統不會放東西進去）。

B 系統（軍師中午建的橋接）試圖填 pending_distill/，但被 A 系統某個 watcher 又搬走（證據：今天 12:21、15:55 投遞的 3 個 .txt 跑到 `distilled/` 子夾去了，檔名沒改、mtime 沒改）。

結果：A 持續做事（distilled/ 有今天 10+ 個 .txt），但**沒人推進度給教練**。教練只收到 C cron 報「空」。

---

## 🎯 修復目標

1. **保留 A**（它穩定運作中）
2. **移除 B**（軍師中午的 launchd 橋接已沒必要）
3. **改 C 的 prompt**：從「看 pending_distill」改成「讀 distilled/ 今日內容 → 寫今日總結 → 推 Telegram」

修完後，教練每 4 小時收到一份**今日對話蒸餾總結推播**到自己 Telegram（6124913915）。

## 🛠️ 執行步驟

### 步驟 1：移除 B 系統（軍師中午橋接層）

```bash
launchctl unload ~/Library/LaunchAgents/com.bymyway.sync-jsonl-distill.plist
rm ~/Library/LaunchAgents/com.bymyway.sync-jsonl-distill.plist
# 橋接腳本本身留著（無害），改名加 .deprecated
mv ~/.openclaw/workspace/scripts/sync_jsonl_to_pending_distill.py \
   ~/.openclaw/workspace/scripts/sync_jsonl_to_pending_distill.py.deprecated-20260616
```

**驗證**：
```bash
launchctl list | grep sync-jsonl-distill   # 應該無輸出
ls ~/Library/LaunchAgents/com.bymyway.sync-jsonl-distill.plist 2>&1   # No such file
```

### 步驟 2：清掉殘留的 pending_distill 內容（如果有）

```bash
ls ~/.openclaw/workspace/terminal-notes/pending_distill/
# 如果有檔案，搬到 done_distill/
mv ~/.openclaw/workspace/terminal-notes/pending_distill/*.txt \
   ~/.openclaw/workspace/terminal-notes/done_distill/ 2>/dev/null || true
```

### 步驟 3：找出 C 系統 cron 的 ID

```bash
openclaw cron list 2>&1 | grep "終端機對話全自動蒸餾"
```

把第一欄 UUID 記下來（變數 `CRON_ID`）。

### 步驟 4：用 `openclaw cron edit` 改 prompt

新 prompt 設計（注入 message 欄位）：

```
【終端機對話蒸餾總結任務（每4小時）】

請執行以下步驟：

步驟一：列出今天的蒸餾檔
- 執行：ls -lat ~/.openclaw/workspace/terminal-notes/distilled/*.txt | head -20
- 找出今天台灣時間（Asia/Taipei）的所有 .txt 蒸餾檔

步驟二：讀取今天的蒸餾內容
- 把今天的所有 .txt 內容讀進來
- 如果今天沒有檔案，直接回報「今日無新蒸餾對話」並結束

步驟三：總結成精華
- 用 200-400 字總結今天教練：
  * 關心了什麼主題
  * 解決了什麼問題
  * 有什麼重要決策或承諾
- 保留教練說過的關鍵原話（用引號）

步驟四：推播給教練
- 直接把總結用繁體中文發到 Telegram（這是本任務的 announce 動作）
- 訊息格式：
  📊 *過去 4 小時對話蒸餾*
  
  （總結內容）

完成後一句話回報：總結了幾個 session、總字數多少。
```

執行 edit：

```bash
# 注意：openclaw cron edit 的具體用法看 --help
openclaw cron edit --help
openclaw cron edit $CRON_ID --message "（上面那段 prompt）"
```

如果 `edit` 不支援改 message，改用「先 rm 再 add」：

```bash
openclaw cron rm $CRON_ID
openclaw cron add \
  --name "🔴 終端機對話總結（每4小時推播）" \
  --schedule "0 */4 * * *" \
  --tz "Asia/Taipei" \
  --agent main \
  --model "minimax/MiniMax-M3" \
  --announce telegram:6124913915 \
  --best-effort \
  --message "（上面那段 prompt）"
```

**驗證**：
```bash
openclaw cron list 2>&1 | grep -E "終端機對話總結"
openclaw cron run <新ID>   # 立刻試跑一次，看 Telegram 有沒有收到
```
