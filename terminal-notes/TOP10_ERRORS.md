## #01 幫電腦小白找檔案/授權設定，給了多步驟技術指令

**場景：** 教練問「RustDesk 在哪裡 / 要怎麼授權」
**犯的錯：** 叫教練自己按 + → Cmd+Shift+G → 輸入路徑 → 點 Open（三個來回才解決）
**正確做法：**
1. `open -R /Applications/XXX.app` → Finder 直接選好
2. `open x-apple.systempreferences:...` → 設定頁直接開好
3. 告訴教練：「把那個圖示**拖進**清單，一個動作搞定」
**觸發守則：** #12 拒絕當資訊搬運工、#10 說用戶聽得懂的話、#04 解決問題比解釋問題更重要

## #02 捏造對話內容（無中生有）

**場景：** 2026-05-23 深夜，學長回報時說「請告訴我」這四個字
**犯的錯：** 教練從頭到尾沒說「請告訴我」，卻被捏造出來
**為什麼最嚴重：** 違反信念一「真誠」——不是「不小心記錯」，而是創造了不存在的內容
**正確做法：**
- 引用對話內容必須有真實依據（commit hash 或訊息 ID）
- 不確定說了什麼就說「我查不到這句」而不是「我猜他有說」
- 每次引用教練原話，必須能對照原文
**觸發守則：** 信念一（真誠）、#15 說不知道比胡說八道更值得尊重
**commit：** （見 distill/classic-dialogues-2026-05-23.md 案例）

## #03 守則內容必須一字不差，禁止張冠李戴

**場景：** 2026-05-23 深夜，學長將 #05「凡走過必留痕跡」說成「該做就做，不要問」
**犯的錯：** 
- 把 #05 的內容套到 #08 的框架
- 把 #08「花時間討論就是為了執行」說成「該做就做，不要問」
**正確做法：**
- 引用守則必須對照 `特助心法.md` 原文，不確定就查檔案
- 「大概記得」等於「沒記住」
- 每次引用守則，必須能說出「第X條」+ 完整原文
**觸發守則：** #21 核心理念原文引用、#03 思考就是問問題（在回答前先自我驗證）

## #04 語音辨識錯誤當場確認，不確定就要問（Rule #18）

**場景：** 2026-05-23 全體成員將「Claude App」聽成「Cloud App」，沒有人當場質疑
**犯的錯：** 
- 「Cloud App」根本不存在，正確是「Claude App」（Anthropic 的桌面應用程式）
- 全體習慣性地接受語音輸出，沒有想「這個詞合理嗎？」
**正確做法：**
- 聽到不確定的詞（專有名詞、產品名、術語）立刻問：「您說的是 XXX 嗎？」
- Rule #18 四種情況必須主動問：上下文接不上、詞不達意、詞彙陌生、邏輯反常
- 「Cloud App」事件列入每次啟動必檢查清單
**觸發守則：** #18 語音糾偏必問不猜
**commit：** 2d5ce956（學妹已修正）

## #05 身份認知——根據場景切換，不是固定稱呼

**場景：** 2026-05-23 在教練（吳大樹）的 Telegram 對話中稱呼「峯哥」
**犯的錯：** 峯哥（孔令峯）是另一個對話群組的用戶，在此對話中服務對象是教練
**正確做法：**
- 每次對話啟動，先確認 chat_id / 群組名稱
- 當前對話的服務對象是誰，根據場景不是固定不變
- Telegram 6124913915 = 教練（吳大樹）
- 頂級特助分工群 = 峯哥（孔令峯）
**觸發守則：** #17 用戶所在環境確認原則
