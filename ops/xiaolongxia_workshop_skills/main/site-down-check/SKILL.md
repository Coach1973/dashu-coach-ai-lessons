# 網站打不開／健康檢查（2026-10-16 建立）

起因：10/16 17:03 教練傳 angel-sister「修一下，無法顯示」，當時整個 `/curated/` 都 404，真正原因是工作資料夾被另一個 AI 拉錯分支換掉（網站名冊不見）。只回「404」教練聽不懂、也沒人接手。

## 步驟

1. **實測教練給的網址**（加隨機參數避開快取）：
   `curl -sL -o /dev/null -m 15 -w '%{http_code}' "<網址>?v=$RANDOM"`
2. **跑系統健康檢查**（約 1 分鐘，只讀不改）：
   `python3 ~/.openclaw/workspace/scripts/system_health_check.py`
   最後一行是總結；⚠️ 那幾行就是問題。
3. **判斷原因，用白話講**：
   - 只有這一頁壞、其他都 ✅ → 這一頁本身的問題（檔案、圖片太大、網址打錯）。查 `~/github_repos/<網址最後那段>/` 在不在。
   - 一整群頁面都壞（例如 `/curated/` 全部 404）、或健康檢查有 ⚠️「工作資料夾」「自動服務」 → 系統層問題，交給軍師（下一步）。
   - 全部 ✅ 但教練說打不開 → 多半是快取：請對方等 1～2 分鐘後重新整理；LINE 裡打不開就用瀏覽器開。
4. **要軍師處理的，直接寫信**（不是叫教練去講）：寫到 `~/.openclaw/workspace/cross-agent/inbox/mac/`，檔名 `YYYYMMDD-HHMM_xiaolongxia-to-mac_site-down.md`（資料夾不在就建），內容：哪個網址、實測狀態碼、健康檢查的 ⚠️ 原文、教練原話。寫完 `git -C ~/.openclaw/workspace add` 那封信再 commit＋`push origin main`（workspace 分支是 main，先 `git branch --show-current` 確認）。
5. **回覆教練 3～5 行白話**：哪裡壞、為什麼、現在誰在處理（或已經好了）。不貼整份輸出、不寫英文術語、不寫「請您去…」。網址獨立一行。

## 不要做
- 不要自己重啟服務、刪檔、切分支（那是軍師的工作，守門員也會自動補設定檔）。
- 不要只回「404」或「連線錯誤」就結束。
