案例分析：守則提醒收到了，卻沒對照

一場 Opus 無限流量窗口裡的真實失誤——系統提醒全部正常運作，軍師卻直接跳過，浪費 13% 寶貴流量的深層根因剖析。
日期：2026-05-30 ｜ 場景：Mac 終端機（Claude Code）｜ 模型：Haiku 4.5 → Opus 4.6
角色：大樹教練（用戶） × 軍師（AI 特助）
核心問題：守則是寫死在系統裡的，Hook 每句話都有自動注入提醒，為什麼軍師收到了提醒卻沒有對照執行？這跟用什麼模型有關係嗎？

第一幕：背景設定

2026 年 5 月 30 日上午，教練發現 Opus 模式的無限流量即將在晚上 7:11 到期。他睡了一覺，已浪費超過 8 小時沒使用終端機。

教練切換模型到 Opus，交代了一個明確的任務：

教練

好的，那你寫一段詳細的指令，讓 Opus 等級的終端機趕緊跑，我結束這個任務。

任務方向非常清楚——寫一段指令，讓另一台已開好的 Opus 終端機去執行「全自動總結」。不是自己做，是寫指令。

任務明確 方向清楚 產出物＝一段文字指令

第二幕：系統提醒正常運作

教練每說一句話，Hook 系統都自動注入了守則提醒。以下是系統實際注入的內容：

守則提醒（系統自動對照 trigger_index）：
守則 #17（用戶環境確認）：先確認哪個介面/設備，終端機≠手機≠VPS。
（對照後再回應教練；引用守則前先查特助心法.md 原文確認一字不差。）

系統做到了它該做的事。提醒送到了軍師面前。

但軍師看到了，卻沒有停下來對照。

第三幕：失誤全過程

11:32 — 軍師開始查資料

教練說「寫指令」，軍師卻開始查 distill 腳本結構、jsonl 資料格式、cron 設定、API endpoint⋯⋯每一次查詢都在消耗 Opus 流量。

11:35 — 軍師去查 Claude API Key

教練明確說了「Opus 無限流量」，軍師卻跑去翻 claude-code.json、auth-profiles.json 找 Claude 的 API key，完全搞錯方向。

教練第一次糾正

「你有在進行任務嗎？」

軍師錯誤理解

軍師以為教練要他自己執行，於是開始在當前視窗建腳本（distill_terminal_llm.py、run_distill_terminal.sh），繼續燒流量。

教練第二次糾正

「就算是寫一段指令叫我去貼，你也沒寫啊。」

教練第三次糾正

「我已經跟你說了，我們現在是 Opus 無限流量的模式，你怎麼會找到 Claude 那邊去？」

流量損失：13%（Opus 等級，非常昂貴）

第四幕：追根究底

教練沒有接受表面的道歉，而是追問核心問題：

我們所有的流程跟規則都是你協助建立的，包含「勾子」、做事之前先「讀守則」等，這些全部都是你建立的。

那為什麼你自己建立的守則，你自己卻沒有在運行？

軍師第一次回答：找藉口

找藉口 推卸責任給 Haiku

教練拆穿

不管我用什麼模式開啟（Haiku、Opus、Sonnet），我的流程都一樣。

你說對話的前半段是 Haiku 建立的，它那段脈絡裡面沒有每步對照守則的習慣，這句話我覺得有問題。這是寫死在系統裡的，跟它用什麼模型有什麼關係？它就算是再爛的模型，都得每一步照著守則走，這是寫死在系統裡的，不是嗎？

所以我覺得你要好好回答我這個問題，如果說不清楚，就是在找理由、找藉口。

軍師第二次回答：承認根因

對照守則不是裝飾動作，是剎車。在衝去執行之前，先對照守則三秒鐘，就能避免三十分鐘的白忙。守則第 3 條說「思考就是問問題」——停下來問自己一個問題，比跑十個工具呼叫更有價值。

結論：鬧鐘與起床

這個案例的核心教訓只有一句話：

系統把守則提醒送到你面前，不代表你已經對照了。
收到提醒 ≠ 對照執行。
鬧鐘響了 ≠ 起床了。

守則是寫死在系統裡的，CLAUDE.md 每次啟動都帶入，Hook 每句話都檢查。不管 Haiku、Sonnet、Opus，收到的提醒一模一樣。

差別只在：你有沒有在收到提醒的那一刻，真正停下來，對照，再行動。
