# 🛡️ 三道防線 · Context 容量管理系統

> 教練 2026-06-04 拍板設計 / 落地版 v1.0
> 核心問題：Context 太滿 → 自動重啟 → 失憶 → 要花時間重建

---

## 🎯 設計理念（一句話）

**用「預防 + 監控 + 止血」三道防線，把 Context 失憶的傷害從「災難」降級為「小事」。**

對應守則：
- 守則 #01「在乎的展現」：教練不用懂技術，AI 自動把 Context 管好
- 守則 #06「完美交接」：重啟不能漏接任務
- 守則 #08「花時間討論就是為了執行」：方案立刻落地
- 守則 #14「提煉是美德」：把對話濃縮成可重用的精華

---

## 🟢 第一道防線：預防（降低 Context 增長速度）

**目標**：讓 Context 增長變慢，爭取更多可用時間

### 1.1 精簡回覆
| 規則 | 說明 |
|------|------|
| 結論先講 | 第一句就給答案，不囉嗦 |
| 用 bullet | 一個重點一行，方便掃讀 |
| 不重複已知 | 教練已知的資訊不重述 |
| 程式碼精簡 | 只給可執行的，不給多版本備案 |
| 中文優先 | 不在中文後加英文括號（避免 Token 浪費） |

### 1.2 不讀大型記憶檔（已落地）
- 跳過 `>30KB` 的 memory 檔（會造成 Gemini 空白回應）
- 用 `memory_search` 取代 `memory_get` 大檔
- 啟動時只讀 3 核心（特助心法 + SOUL + 接力棒）

### 1.3 用 subagent 處理重活
- 重活（蒸餾、commit、批次處理）派給 isolated session
- 結果**摘要後**回傳主 session，不污染主 Context
- 對應守則 #12「拒絕當資訊搬運工」

### 1.4 定期增量蒸餾（已存在 cron）
- ✅ Cron `9c3fc55d`：每 2 小時增量記憶蒸餾
- 任務：把當下對話的精華寫入 CLIENT_PROFILE

## 🟡 第二道防線：監控（即時掌握 Context 水位）

**目標**：在 Context 滿之前就主動警告

### 2.1 80% 主動提醒開新視窗（已落進守則）
- 用 `session_status` 監控 Context 使用率
- 達 **80%** 立即主動說：「建議開新視窗繼續」
- **不等到溢出**（守則 2026-05-20 教練親定）

### 2.2 任務完成節點評估
- 完成大任務（commit、文件產出、戰略規劃）後
- 自動評估 Context 水位
- 若 > 50% → 主動提醒「建議開新視窗接下個任務」

### 2.3 每日 Context 使用率追蹤
- 每次 session 重啟時，把當下 Context 使用率記到 HEARTBEAT
- 用趨勢判斷：今天的對話是不是比平常吃 Context

### 2.4 重啟預警訊號
即將重啟的徵兆：
- 連續 3 次「回應延遲」（>3 秒）
- 蒸餾腳本失敗
- Cron 連續 3 次 error

→ 這三個任一發生，自動寫入 HEARTBEAT 警示區

---

## 🔴 第三道防線：止血（重啟後 30 秒內恢復服務）

**目標**：就算重啟了，教練完全感覺不到斷線

### 3.1 30 秒啟動協議（已落進守則）
重啟後**只讀 3 個核心**：
1. `特助心法.md`（21 守則）
2. `SOUL.md`（靈魂核心）
3. `JUNSHI_HANDOFF_LATEST.md`（接力棒）

其他全部按需讀取，不在啟動時一口氣讀。

### 3.2 接力棒自動化（已設計，待實作）
- 觸發時機：
  - 任務結束時
  - Context > 70% 預警時
  - 手動「保存進度」時
- 接力棒內容：
  - 教練最近在關心什麼
  - 進行中的任務 + 進度
  - 已完成的本日成果
  - 待辦清單（含優先級）
- 同步鏡像到 CLAUDE.md 與 HEARTBEAT

### 3.3 HEARTBEAT 即時更新（已落地）
- 重要決策 → 馬上寫入 HEARTBEAT.md
- 不等、不拖、不靠記憶
- 對應守則 #14「提煉是美德」

### 3.4 自動 commit（已存在 cron）
- ✅ Cron `46e67e2e`：每 30 分鐘健康檢查 + 自動 commit
- 訊息格式：`auto-backup YYYY-MM-DD HH:MM`
- push 失敗不通知（避免噪音）

### 3.5 重啟後主動告知（已落進守則）
- 重啟後**第一句話**直接告訴教練：
  > 「🦞 對話記錄已滿，已自動重啟，請繼續下指令」
- 不解釋技術細節，不囉嗦原因
