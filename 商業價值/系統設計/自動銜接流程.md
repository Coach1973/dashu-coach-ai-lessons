## 1. 為什麼要做

軍師評估報告指出：每次 session 結束靠上一棒軍師寫 `.md`，下一棒靠「開工暗號」觸發，這是手工打造。

教練原話：「你已經設定好的流程，尤其是『自動銜接流程』的部分，一定要寫在系統當中，讓它長長久久地持續下去。」

---

## 2. 自動銜接流程的設計

### 觸發時機（三個）

1. **Session 結束時自動觸發**（最重要）
   - 觸發點：context 用量 > 70% / 用戶說「開新視窗」/ idle timeout
   - 自動動作：寫入 `JUNSHI_HANDOFF_LATEST.md`、鏡像到 `CLAUDE.md`、commit 到 GitHub

2. **每次心跳時自動檢查**
   - 觸發點：每 30 分鐘
   - 自動動作：檢查接力棒是否過期（>24h）、是否最新、教練是否有待辦

3. **教練手動觸發**
   - 觸發點：教練說「做交接」/「寫接力棒」/「handoff」
   - 自動動作：立即生成接力棒 + commit

## 4. 實作步驟

### Phase 1：建立自動化腳本
- [ ] 建立 `scripts/auto_handoff.sh`
  - 讀取本 session 對話紀錄
  - 套用模板生成 `JUNSHI_HANDOFF_LATEST.md`
  - 鏡像到 `CLAUDE.md`
  - git commit + push
- [ ] 建立 `scripts/handoff_cron.sh`
  - 每 30 分鐘檢查 context 用量
  - 超過 70% 自動觸發 handoff
- [ ] 建立 `scripts/handoff_trigger.sh`
  - 教練說「做交接」時觸發
  - 立即執行完整 handoff 流程

### Phase 2：建立交接品質檢查
- [ ] 接力棒是否包含「完成了什麼」
- [ ] 接力棒是否包含「待辦清單」
- [ ] 接力棒是否包含「教訓」
- [ ] 接力棒是否包含「下一棒建議」

### Phase 3：長長久久持續
- [ ] 寫入 OpenClaw 的 hook 機制（session start / session end）
