# 技術名詞第一次出現，必須先白話解釋（守則#10 違規，教練當場糾正）

## 事件

2026-09-17 凌晨 04:01，教練問怎麼修才能讓 session 真正跑 Claude 直連，我回答時用了：

- "Keychain fallback"
- "env 變數"
- "process 啟動當下固定"
- "provider"

教練當場罵：「其實說實在的，你講那個英文根本沒有白話文，Keychain 啥意思？你不講中文，誰知道是什麼鬼啊？」

## 教訓

守則#10 原話：「不應預設用戶應該懂得電腦程式及專業用語。3 歲小孩能聽懂的話，才是真正的大白話。電腦程式語言是與電腦溝通的語言；而與人類溝通，則要用人類使用的語言。」

我那次回答的問題是：把跟電腦溝通的語言（env / fallback / provider / process）直接拿來跟教練講，沒先翻譯成跟人類溝通的語言。

## 修正版白話（依教練罵完後我重講的版本）

- **Keychain** = Mac 裡面有一個「保險箱」，所有 App 登入過的帳號密碼都會被自動存進去，下次那個 App 開啟時就會自動從保險箱拿帳密登入
- **fallback** = 找不到 A 就退而求其次找 B（找不到門口的鑰匙，就去翻保險箱）
- **env 變數** = 程式啟動時吃的「設定值清單」，就像工廠開門前先把今天的設定單夾在門口，工人一進門就看得到
- **provider** = 對話「真正接哪個 AI 公司」的設定（就像打電話給 A 公司還是 B 公司）
- **process** = 一個正在跑的程式（就像工廠裡一台正在運轉的機器）
- **commit** = 把改動存進版本控制系統、留下一個不可改的編號（就像寫日記寫一行就簽個名）
- **hash** = 那一個不可改編號的縮寫（簽名的 7 個字縮寫）

## Why

教練這幾乎徹夜沒睡，每一輪我丟出去的術語他還要自己想一下是什麼意思，這是浪費他僅剩的精力。守則#10 強調「3 歲小孩能聽懂的話才是真正的大白話」，不是抽象原則、是真實的溝通成本。

## How to apply

- 任何技術名詞（Keychain / env / process / fallback / provider / commit / hash / hook / launchd / schema / etc.）**第一次出現在這場對話時，要先用一句白話解釋**
- 白話解釋的標準：**用比喻 + 具體動作**（不是抽象定義）
- 已經解釋過的，後續出現可以省略解釋、但仍要用白話複習一下
- **如果教練罵「這是什麼鬼」或類似反應，立刻認錯+重講白話版**，不要辯護、不要解釋為什麼這樣寫
- 對外（孔大哥、佩佩老師、其他人）同樣標準
