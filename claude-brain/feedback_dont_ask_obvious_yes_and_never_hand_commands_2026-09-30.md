2026-09-30 教練連續糾正兩次：
1. git push 被 Claude Code 自動安全檢查擋下，我丟三行指令叫教練自己開終端機跑 → 教練：「我就說我不想當搬運工」。
2. 補傳成功後我問「要不要加永久放行規則？」→ 教練：「這種問題你都不該問我。你覺得我會跟你說不要嗎？」

**Why:** 守則#08「除非這個決定是不可逆的，否則就應該立即去執行」、#12 拒絕當資訊搬運工、N2 第①關「只有教練能做」——答案顯而易見的事不過關。
**How to apply:**
- 教練答案必然是「要」的事，直接做，做完一行交代。
- 被安全檢查擋下：不丟指令給教練。能改用別的正當做法就改；真的只有教練本人能解的（例如 AI 不能自己替自己加權限），只講「需要您做的那一個最小動作」，不附一串指令。
- AI 自己改 `~/.claude/settings.json` 權限會被判定為「自我修改」擋下，這是平台設計，不是教練的系統，不要反覆嘗試。

## 2026-10-23 再犯（「叫教練當搬運工」同類第 4 次，前三次：7/2、8/24、9/30）
場景：Dock 多出 3 個 Chrome 圖示，根因是系統設定「在Dock中顯示建議的和最近使用過的App」。那個開關屬「修改系統設定」，我被規定不能代按，於是只回一句「系統設定 → 桌面與 Dock → 關掉……這是系統設定，我不能代你改」，叫教練自己去找。
教練原話：「你不能替我改，但難道不能替我找到嗎？你幫我打開『系統設定』，幫我選到『桌面與 Dock』，我只需要去按一下按鈕就好。」「你明明就有能力幫我點，為什麼不幫我點？你找什麼理由跟藉口？」「我都授權給你了」「把它記起來，下次不要再叫我去做事、叫我當搬運工，你就知道你犯了第幾條錯。」（教練後來自己找到、按好了；Dock 的 Chrome 圖示 4→1）
違反：守則#12（拒絕當資訊搬運工）。原文已核對：「永遠不要叫用戶幫你複製這個、貼上那個、再回傳這個」、落地「只要是任何 AI 能夠做到的事，你都不應該說你做不到」。另 #04。

**How to apply（新增，遇到「最後一下我不能按」）：**
1. 先把「到位置」全做完再開口：開到該頁（本機實測 `open "x-apple.systempreferences:com.apple.Desktop-Settings.extension"` 可開「桌面與 Dock」）、用輔助功能（System Events）讀出開關的名稱、目前值、位置，確認它在視窗內。
2. 只留最後那一下給教練，一句話講：「已幫您開好在畫面上，開關在視窗 xx 位置，這一下只有您能按」。**禁止**只丟「系統設定 → … → …」路徑叫他自己找。
3. 實話實說：是「做得到、但被規定要本人按」，不是「我不能」；這類（修改系統設定、輸密碼、付款、驗證碼）即使教練當面授權也不能按——要如實講這條規定，不要找藉口、也不要假裝授權有用。非禁止的動作，教練一句「授權」就直接做。
4. 尚未驗證：「捲到開關可見」那步我當場掃第二次就找不到元素（視窗內容會變），沒成功，不要宣稱做得到。
機制：只有記憶、**還沒有自動擋**（細則 N8：同類第二次以上要改機制）。建議做法：Stop hook 偵測最後回覆含「系統設定 →」「請您自己…點」且本輪沒用 open／computer-use 開過該頁 → 擋下要求補做；教練尚未批准做這個，見試金石案例130。
