2026-08-14申請Cloudflare API Token過程中，先幫教練加`go.bymyway.com`的DNS紀錄，卡在Cloudflare新版介面的「Welcome to new DNS experience」導覽彈窗——用claude-in-chrome試了單擊/雙擊/Escape/點Close/點Got it共十幾次都無法讓表單真正打開（事後證實是彈窗攔截了自動化點擊事件，教練親手滑鼠點一次就徹底解除，之後同一支自動化流程立刻正常）。當下判斷改請教練手動輸入六個欄位值完成這筆設定。

教練事後明確表態：「雖然這一次是我手動去完成的，但是這並不是我滿意的，因為過去這一類的操作都是你去完成的。」

**Why：** 教練的預設期待是——只要是網頁/瀏覽器類操作，全部都該由AI完成（[[feedback_no_paste_terminal_results]]同一種精神的延伸），手動介入是例外不是常態。單純把整個任務丟回給教練「你自己填一填」，即使有技術上的正當理由（自動化工具真的點不動），也會被感受成偷懶或退讓，而不是解決問題。

**How to apply：**
1. 遇到瀏覽器自動化卡住，先窮盡合理的排除手段（試不同點擊方式、關閉可能攔截的彈窗/教學導覽、加等待時間），這點本場有做到。
2. 若仍然卡住，**不要把整個任務都改成手動**——精準定位卡在哪一個具體元件（例如這次是「導覽彈窗攔截點擊」），只請教練做「解除那一個障礙」的最小動作（例如「幫我點掉那個彈窗」），障礙一解除，其餘步驟自己接手完成，不要連帶著把後面本來可以自動化的步驟也一起丟給教練。
3. 障礙真的解除後，要主動回頭驗證自己現在能不能操作了（本場後來確實驗證「Add record」表單能正常開啟），並誠實跟教練說明「卡住的原因是什麼、現在解除了」，讓教練理解這不是能力問題，是特定元件的一次性技術障礙。
