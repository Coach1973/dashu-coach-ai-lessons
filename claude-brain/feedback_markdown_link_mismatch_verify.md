# 🔴 markdown 連結格式跑掉，一律視為高風險信號（2026-07-11 案例47）

教練貼的訊息若含 markdown 連結，且**顯示文字跟實際 href 對不上**、或**連結後面緊跟著沒有空格的文字**，這是複製貼上/格式轉換跑掉的明顯信號，不是可以隨意二選一的正常輸入。

## 錯誤示範（本次真實發生）
教練貼：`[https://coach1973.github.io/](https://coach1973.github.io/goeasy-ai/)ai-talk`
顯示文字是 `https://coach1973.github.io/`，href 卻是 `https://coach1973.github.io/goeasy-ai/`，後面黏著「ai-talk」沒空格。
軍師沒有起疑，直接照 href 字面認定「ai-talk 是 goeasy-ai 子路徑」，動手搬檔案、commit 驗證，回報「完全對齊」。教練用反問句「這樣你有理解我的意思了嗎？」給了糾錯機會，軍師卻只驗證自己操作有沒有做對（git status），沒有回頭質疑理解本身對不對，直到教練第三次用純文字網址點破才真正搞懂。

## How to apply
1. 看到顯示文字與 href 不一致的連結 → 先問「我看到的網址是 XXX，這樣對嗎？」，不要選一種解讀直接動手
2. 教練用「這樣你有理解我的意思了嗎」這類反問句時 → 回答前重新核對**原始輸入有沒有被誤讀**，不是只驗證自己的操作對不對
3. 對有歧義輸入的解讀，回報時不要用「完全對齊」這種斬釘截鐵的措辭——語氣篤定程度要跟實際查證可靠程度成正比

## Why（教練 2026-07-11 親口點破的核心）
「你真正要檢討的是，就因為這個小錯誤，我就得坐在電腦前面重複說三次，還要打字、還要再修改網址。最可怕的就是這在浪費我的時間。我都是犧牲睡眠、犧牲很多的事情坐在電腦前面工作，這種低級錯誤，沒必要地讓我重複講了兩三次，這才是最嚴重的地方。」

**評分標準是「教練要花多少他犧牲睡眠換來的時間把我拉回正軌」，不是「這件事本身對不對」。** 多花 5 秒主動問一句，永遠比讓教練事後花 3 分鐘打字校正划算。任何會導致教練「再打字/再確認/再講一次」的情境，不論最終有沒有做對，都算成本。

對應執行細則 E07「遇到邏輯反常主動問，不照字面瞎猜」。詳見試金石案例47。
