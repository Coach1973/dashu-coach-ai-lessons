# 🔴🔴🔴 永久鐵律：不准問教練「記不記得」，要自己查證

## 事件（2026-07-08，聯想機）

查 Chrome 搬家時，E 槽目的地資料夾出現一批 C 槽現在完全沒有的舊資料（Bookmarks、History、Google Profile Picture）。我當下直接問教練：「你有沒有印象，Chrome 書籤或瀏覽紀錄最近是不是曾經『變空』過？」

教練當場糾正，原話：

> 「你不要問我有沒有印象，我們每做一件事都有記錄、有上傳，你是自己不會去查？那一大堆資料在電腦裡面，就是讓你去查的。我們的習慣就是做到什麼地方都一定會有個記錄，都會 GitHub 上傳，也都會交接……除此之外，你去讀完整的資料，該幹嘛幹嘛去，不要那麼笨好不好？」

「凡走過必留痕跡，有時間戳記、有 Commit、有 GitHub……如果我的腦袋裡面能記那麼多細節，要你何用？」

事後我改為直接查 `git log --grep`，5 分鐘內就在 commit `737bd140` 找到根因（宏碁機曾經整包 junction 瀏覽器導致三個帳號遺失的教訓），完全不需要問教練任何一句話。

## Why

**這件事教練已經用多個角度講過**，本質相同：
- [[feedback_verify_dont_relay_secondhand_claims]]（2026-07-02）：不接受轉述證據，要親自查證
- [[feedback_no_paste_terminal_results]]：教練說「完成了」要自己 ls/cat 查結果，不准叫教練貼
- 守則 #12（拒絕當資訊搬運工）＋ 守則 #15（說不知道比胡說八道更值得尊重）

這次的新角度是：**連「問教練本人回想細節」都算是失職**，因為教練的工作習慣本來就是「凡走過必留痕跡」——每一件事都有 commit、有時間戳、有 GitHub 紀錄、有交接文件。問教練等於是要教練用大腦記憶體去做 AI 應該用查詢工具做的事，這是本末倒置，也是浪費教練的時間成本（三大信念之二）。

## How to apply

**遇到任何「這件事以前發生過嗎／教練你記得嗎／有沒有印象」的念頭時，先自己查，不准開口問教練。**

### 查證方向優先順序（這次事件梳理出的系統）

1. **Git commit log**（最快、最結構化）
   `cd mac-openclaw-workflows && git log --oneline --all -i --grep="關鍵字"`
   找到 commit hash 後 `git show <hash>` 看完整改動內容和說明文字。這是第一步，通常幾秒鐘就能定位到根因。

2. **試金石案例庫.md**（`試金石/試金石_案例庫.md`）
   查有沒有同類型的已知地雷/教訓。這裡是「濃縮過的教訓」，比翻commit更快抓到「為什麼」。

3. **memory/\*.md 記憶檔**（`claude-brain/` 或本機 `.claude/projects/*/memory/`）
   先查 `MEMORY.md` 索引關鍵字，再讀對應檔案，抓「當時的判斷和脈絡」。

4. **HEARTBEAT.md / JUNSHI_HANDOFF_LATEST.md**
   查最近幾棒在做什麼、有沒有留下待辦或已知問題。

5. **distill/\*.md**（每日蒸餾摘要）
   如果 commit 訊息不夠詳細，蒸餾檔案通常有更完整的當天敘事脈絡。

6. **原始對話紀錄**（`.claude/projects/*/*.jsonl`）
   前面五項都查不到夠精確的答案時，直接讀當天的原始逐字稿——這是最終、最完整的事實來源，教練跟 AI 的每一句話都在裡面。

7. **即時系統現況（最終仲裁者）**
   前六項都是「歷史紀錄」，回答的是「當時發生了什麼、為什麼這樣做」；但「現在是不是還是這樣」永遠要以**直接查詢當下的實際狀態**為準（檔案是否存在、Junction 指向哪裡、資料時間戳等）。這場對話本身就示範了好幾次：記憶檔案說的和實際查證結果不一致時，永遠相信現在查到的實況，並回頭更新過時的記憶（見同場對話裡的 LINE 備份過期判斷、Windows.old 是否真的清除等案例）。

**簡言之**：1~6 回答「為什麼／發生過什麼」，7 回答「現在還是不是這樣」，兩者都不能用「問教練」取代。教練的大腦不是資料庫，AI 自己有能力查的東西，永遠不該讓教練用記憶力代勞。
