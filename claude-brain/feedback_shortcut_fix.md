# 試金石：修 LINE 桌面捷徑圖標（五次全錯）

> 這是 AI 在教練面前最丟臉的一次。教練用 4 個步驟自己解決的事，AI 做了 5 次沒有一次對。這份記錄是永久的教訓。

## 一、問題

LINE 搬家到 E 碟後，桌面上的 LINE 捷徑圖標變成白色通用圖示（不是綠色 LINE 標誌），點了也無法啟動。但工作列（Taskbar）上釘選的 LINE 圖標是正常的、能正常啟動。

## 二、教練明確給的線索

> 「工作列那個是正常的圖示，你就從工作列那個圖示複製一個到桌面不就得了嗎？」

教練已經把答案說出來了。正常的參照物就在眼前。

## 三、AI 的 5 次錯誤嘗試

| 次數 | AI 做了什麼 | 為什麼錯 |
|------|------------|---------|
| 1 | 用 WScript.Shell 新建 .lnk，指向 LineLauncher.exe | Windows 把 junction 解析成 E 碟真實路徑，圖標還是錯 |
| 2 | 複製 Start Menu 的捷徑到桌面 | Start Menu 那份本身就是壞的 |
| 3 | 手動設定 IconLocation 為 LINE.ico | 路徑又被解析成 E 碟，圖標顯示不出來 |
| 4 | 寫 VBS launcher 腳本繞過路徑問題 | 過度工程化，圖標依然不對 |
| 5 | 用 AppX shell:AppsFolder 啟動 | MSIX 包資訊已經過期，無法使用 |

**共同根因：從頭到尾沒有去查「工作列那個正常的」到底指向哪裡。**

## 四、教練自己怎麼解決的（4 步）

1. 在工作列對 LINE 圖標點右鍵
2. 彈出的 LINE 圖標再點一次右鍵，按「內容」
3. 複製「目標」欄位的路徑
4. 在桌面右鍵 → 新增捷徑 → 貼上路徑 → 完成

就這樣。4 步。圖標正確、路徑正確、能正常啟動。

## 五、教訓（永久生效）

**Why:** 教練明確說「這個是正常的」，等於直接給了正確答案的位置。AI 卻忽略這個線索，自己用技術手段反覆猜測，同一個思路（WScript.Shell 建 .lnk）的變體試了 5 次，每次都被 Windows 路徑解析打敗。

**How to apply:**
1. **教練說「這個能用/這個正常」→ 第一件事就去查那個能用的東西，照抄它的設定**
2. **同一方法失敗 2 次，必須換做法，絕不第 3 次**（守則 #07 失敗兩次換路）
3. **簡單方案優先**（守則 #16），教練 4 步能完成的事不需要寫 VBS 腳本
4. **教練的話就是最重要的線索**（守則 #13 用戶說的話 = 存在價值），不是背景噪音

## 六、驗證題（AI 自證已讀）

1. 教練說「工作列那個是正常的」，AI 第一步該做什麼？ → 去查工作列那個捷徑的實際路徑和設定
2. 同一方法失敗幾次必須換？ → 2 次
3. 教練 4 步解決的事，AI 為什麼做了 5 次？ → 因為沒去看教練指出的正常參照物，自己閉門造車
