# 試金石案例 30：強制殺進程導致 Zoom 會議連結失效

> 教練親口：「很影響我工作，尤其是 ZOOM 會議，赴不了約，責任誰擔？」
> 這條教訓用教練的行程換來，永久生效。

## 一、事故經過

1. 做 AppData 資料夾 junction 搬移前，AI 用 `Stop-Process -Name "Gan Jing Browser" -Force` 強制關閉瀏覽器
2. 搬移完成後，教練用瀏覽器點 Zoom 會議連結，**只出現網頁、無法自動開啟 Zoom 進入會議室**
3. 診斷發現：Windows 層的 `zoommtg://` 協定完全正常，問題在瀏覽器層
4. 根因：瀏覽器「允許 Zoom 開啟外部連結」的權限存在**記憶體**裡，正常關閉才會存回磁碟。`-Force` 強制殺掉 = 沒存到磁碟 = 權限消失

## 二、鐵律（永久生效）

**Why:** 教練的 Zoom 會議連結失效，差點赴不了約。瀏覽器協定權限、未存的表單、未關的分頁——這些都是「強制殺進程」的副作用，代價可能是教練的生意和信譽。

**How to apply:**

| 規則 | 說明 |
|------|------|
| 🔴🔴🔴 **禁止 `Stop-Process -Force` 關閉瀏覽器** | 瀏覽器必須由教練**手動正常關閉**（點 X）才能保存設定 |
| 🔴🔴🔴 **任何 App 搬家前，先請教練手動關閉** | 不要用程式強制殺，代價太高 |
| 🔴🔴 **搬家後驗收要測完整使用流程** | 「App 能啟動」≠「功能正常」；Zoom 要測點連結進會議室，不只是開啟程式 |
| 🔴 **與工作直接相關的 App（Zoom、LINE、Signal）搬移前必須告知風險** | 讓教練決定時間點，不在會議前後操作 |

## 三、正確 SOP（搬移有瀏覽器或通訊 App）

1. **先問教練**：「現在有重要會議嗎？建議找空檔再做」
2. **請教練手動關閉**所有要搬的 App（不用程式殺）
3. 確認進程完全消失後再開始 robocopy
4. 搬完建 junction 後，**請教練自己開 App 測試完整功能**（不只是「能啟動」）
5. 特別確認：瀏覽器點 Zoom 連結能進會議、LINE 可以收發訊息

## 四、驗證題（AI 自證已讀）

1. 搬移瀏覽器資料前，應該怎麼關閉瀏覽器？→ **請教練手動點 X 正常關閉，禁止 Stop-Process -Force**
2. Zoom 「能啟動」算驗收通過嗎？→ **不算，要測點會議連結能自動進入會議室**
3. 為什麼 -Force 殺瀏覽器會讓 Zoom 連結失效？→ **瀏覽器協定權限存在記憶體，強制殺掉沒有存回磁碟**
