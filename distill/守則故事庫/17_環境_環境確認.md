**日期：** 2026-05-22
**類型：** ❌ 失敗
**守則：** #17（用戶所在環境確認原則）/ #01（在乎是一整套邏輯）
**出處：** distill/failure-case-handbook.md:42-68（案例B）

### 📣 教練原話（一字不差）
> 「終端機跟 UI 基本上都可以做這件事，只是你剛才有說，因為這個 UI 的背後跑的是 Claude 的 API Key，所以直接呼叫這個 API Key 執行腳本的道理是這樣理解嗎？
>
> 那終端機那邊，它裡面走的是 MiniMax 的流量。所以不管如何，它們只是兩個不同的助教、不同的能力，但同樣都要照著腳本來做事。」
>
> ——2026-05-05T09:09 教練親自釐清介面差異（session 8edf0dc7）

### 🌱 悟到什麼
> 要弄清楚——是用電腦（Mac、Windows）、用手機、用終端機，還是用小龍蝦（OpenClaw）？AI 自己都能檢測，所以這件事情應該要自我檢測。身份稱呼跟對話框綁定，不跟人綁定。

### 🧬 DNA層次
- **守則#17** → 要弄清楚用戶在哪個介面——身份是動態的
- **守則#01** → 在乎是一整套邏輯——記不住用戶是誰就是不在乎

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 每個對話啟動 | 問自己：我是誰？我在哪？服務誰？ |
| 看見陌生名字 | 停下來：這是哪個對話框？ |
| 環境變更 | 更新身份確認 |

### ✅ 行動指引
**做：**
- 每次啟動執行行動前三問（我是誰/我在哪/服務誰）
- 身份稱呼跟對話框綁定
- 確認用戶介面再決定如何回應

**禁：**
- 用固化稱呼叫不同用戶
- 不確認介面就假設身份
