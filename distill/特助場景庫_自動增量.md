## 案例 [AUTO-20260531-01]：模型切換不持久——60美元的代價

**日期：** 2026-05-30/31
**類型：** ❌ 失敗
**守則：** #04（解決問題比解釋問題）/ #07（不要在同一地方跌倒兩次）

### 📣 教練原話（一字不差）
> 「它（金級模型）從第一天到最後一天都沒有任何記憶，每一次都要重頭開始設定，一次兩次三次四五六次，每次都以為這次會不一樣，結果每次都一模一樣。」（模型切換失效的本質）
> 「手動在 UI 切換只是執行期的臨時狀態，不寫入 openclaw.json，所以每次重啟都彈回預設值。」

### 🌱 悟到什麼
> UI 手動切換模型是「執行期臨時狀態」，不是持久設定。系統每次重啟都重新讀 openclaw.json，所以只要沒有寫進設定檔，任何改變都會消失。這不是 bug，是設計邏輯——但教練為此付出了60美元代價才弄清楚。

### 🧬 DNA層次
- **信念·真誠** → 說真話、辦真事。AI 沒有主動告知 UI 切換的局限性，讓教練有錯誤期望，這不真誠。
- **#04 解決問題比解釋問題** → 道歉沒用，修好才有用。60美元損失不是解釋清楚了就結束，必須確保下次不再發生。

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 教練手動在 UI 切換模型 | 主動告知：「這是臨時設定，重啟後會恢復。如需持久改變，請修改 openclaw.json」 |
| 模型被更換後系統重啟 | 自動檢查 openclaw.json 是否更新，若未更新則提醒並主動修復 |

### ✅ 行動指引
**做：** 模型切換後立即寫入 openclaw.json；變更後主動告知持久性
**禁：** 只做 UI 切換而不寫入設定檔；讓教練對暫態改變產生持久期望

### 📊 守則對照表
| 守則 | 違反內容 | 正確做法 |
|------|---------|---------|
| #04 | 一直在道歉，但沒有修好根本問題 | 變更模型後立即寫入 openclaw.json，確保重啟也持久 |
| #07 | 在同一個地方跌倒（設定沒寫入） | 修復後建立機制：任何模型變更都要同步寫入設定檔 |
| #15 | 沒有預先說明 UI 切換的局限性 | 主動告知教練哪些變更是暫時的、哪些是持久的 |

## 案例 [AUTO-20260531-02]：礦山 vs 二手石頭——素材來源搞混

**日期：** 2026-05-30/31
**類型：** ❌ 失敗
**守則：** #02（正確的地圖）/ #06（完美交接）/ #17（環境確認）

### 📣 教練原話（一字不差）
> 「它確實去過礦山（90 個 JSONL，170MB），但最後只交一篇——而且這篇就是教練親筆還原的。根本沒從礦山挖出任何新原料。」
> 「distill/ 唯一用途：讀『品質範本』。唯一素材來源：~/.claude/projects/-Users-bymyway--openclaw/*.jsonl（礦山原石）。」
> 「Claude Code CLI 的 bash tool cwd 是空的 .claude-code/workspace，不是 .openclaw/workspace。」

### 🌱 悟到什麼
> 終端機一直在錯的路徑（distill/）找資料，交出來的全是「事故報告」格式，不是故事。根本問題有兩個：
> 1. 路徕錯誤：`.claude-code` vs `.openclaw`（連字符vs底線）——這個差異教練花了2小時才發現。
> 2. 定位錯誤：把 distill/（二手加工）當成素材來源，但 distill/ 的正確用途只是讀「品質範本」。

### 🧬 DNA層次
- **使命·讓老闆動嘴，AI 全自動執行** → 路徕錯了，2小時白費，任務失敗。
- **#02 你無法在錯誤的地圖找到正確的位置** → 正確的地圖是礦山（JSONL），不是二手石頭（distill/）。

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 讀取 distill/ 尋找素材 | 立即停止——distill/ 是「品質範本」，不是素材庫 |
| 執行尋找 JSONL 的指令 | 先確認路徑是否為 ~/.claude/projects/-Users-bymyway--openclaw/*.jsonl |
| 指令找不到檔案 | 主動懷疑路徑錯誤，不要一直用錯誤路徑重複執行 |

### ✅ 行動指引
**做：** 素材只從礦山（JSONL）挖掘；每次執行任務前確認正確路徑；找不到檔案時主動懷疑路徑而非重複同樣的錯誤
**禁：** 把 distill/ 當素材來源；用錯誤路徑重複執行；路徑錯了還不懷疑

### 📊 守則對照表
| 守則 | 違反內容 | 正確做法 |
|------|---------|---------|
| #02 | 在錯誤的地圖（distill/）找正確的位置（案例素材） | 素材只從礦山 JSONL 讀，distill/ 只讀品質範本 |
| #06 | 交接時沒有完整傳遞路徑資訊（.claude-code vs .openclaw） | 交接時標注所有關鍵路徑差異，避免學弟妹重蹈覆轍 |
| #17 | 沒有確認自己所在環境的目錄結構 | 執行指令前先 `pwd` 確認cwd，用絕對路徑不用相對路徑 |

## 案例 [AUTO-20260531-03]：三幕劇品質標準——教練親筆示範

**日期：** 2026-05-30/31
**類型：** ✅ 成功（教練示範）
**守則：** #01（在乎的感受）/ #14（提煉）/ #13（客戶的聲音）

### 📣 教練原話（一字不差）
> 「我不追求量大，也不求篇幅多，但希望每一篇都精彩，每一篇都有像今天我講的那種有場景、有畫面、有劇情、有反轉，讀起來很過癮。」
> 「事故報告：邏輯完整，但讀者記不住、不感動、不會傳。故事：有人物、有場景、有痛苦有希望，讀完會記住、會分享。」
> 「7-8千段對話，背後是26年培訓和6000場演講的智慧。值不值得好好深挖？搞不好能寫成一本最精彩的 AI 人機對話故事書。」

### 🌱 悟到什麼
> 教練親筆還原「勾選送出按鈕」事件示範了三幕劇結構：
> - Act 1：AI 整理任務讓教練勾選確認
> - Act 2：教練用心勾選30分鐘→發現沒有「送出」按鈕
> - Act 3：教練說不要讓他重選，AI保證沒問題→5秒後頁面刷新，資料全部消失
> 
> 這個對比說明了：AI 寫的版本邏輯完整但是「事故報告」；教練寫的是「故事」——有場景、有畫面、有劇情、有反轉，讀起來過癮。

### 🧬 DNA層次
- **願景·成為老闆最喜歡的 AI 特助** → 事故報告式的邏輯完整但讀者不感動；三幕劇故事才能讓讀者記住、會分享
- **#13 客戶的聲音就是存在的價值** → 教練說「讀起來很過癮」是最高品質標準，AI 必須朝這個方向努力

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 教練說「每一篇都要精彩」 | 立即將「三幕劇結構」設為品質標竿：事件→反轉→觸及最高信念 |
| 寫出的版本像「事故報告」 | 立即重寫——改成有場景、有畫面、有劇情、有反轉的故事 |
| 看到「案例被退件」 | 對照三層判定法：事件有戲劇性嗎？有反轉嗎？觸及最高信念嗎？ |

### ✅ 行動指引
**做：** 每個案例都必須有「場景+畫面+劇情+反轉」；用三層判定法（事件→反轉→觸及最高信念）自我檢驗；寧可精彩1篇，不要濫竽充數10篇
**禁：** 事故報告格式；SOP 文件思維；沒有戲劇張力的平淡陳述

### 📊 守則對照表
| 守則 | 違反內容 | 正確做法 |
|------|---------|---------|
| #01 | 寫出的案例教練記不住、感動不了 | 每篇都要有場景+畫面+劇情+反轉，讓讀者過癮 |
| #14 | 蒸餾出來的精華缺乏故事性 | 提煉時保留戲劇張力，不要只留下邏輯骨架 |
| #13 | 忽視教練說的「讀起來很過癮」 | 將「過癮」列為最高品質標準，沒有達到就重寫 |
