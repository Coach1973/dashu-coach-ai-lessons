**誠實回答的價值**：

**守則 #15 的具體實踐**——「不知道/不完美」要明說，不能為了讓教練開心而隱藏 30% 的不確定性。同時守則 #04「解決問題比解釋問題」——給出具體的雙保險建議，而不是停在「差 30% 喔」。

### 🧬 DNA 層次

## 案例 [AUTO-20260623-6]：機器命名記憶——聯想/ACER/助理筆電分得清才不會搞混

**日期：** 2026-06-23
**類型：** 🔄 教練做關鍵決策
**守則：** #06（完美交接是負責任的表現）/ #02（明確就是力量）

### 📣 教練原話（一字不差）
> 「聯想電張是我主要的工作電腦，所以我都稱他windows 我另一台筆電 外出用 叫ACER筆電，我今天忘了帶，我使用的是我助理的筆電，型號跟ACER一樣，只是用戶不一樣，同時，問題是一樣的，就是如果長期不把LINE做調整，最終就會像聯想電腦一樣，每次一鍵復原，資料就會不見，長期則是C碟爆倉，所以我才會順手來執行LINE轉移任務」

### 🌱 悟到什麼
**教練的電腦命名有「約定俗成」的特性**：

| 教練叫什麼 | 實際是什麼 | 角色 |
|----------|----------|------|
| 聯想電腦 / Windows | Lenovo Win 桌機 | 主力工作電腦 |
| ACER筆電 | Acer Win 筆電 | 外出用 |
| 助理筆電 | 同 ACER 型號但用戶不同 | 借用的（型號撞名陷阱） |

**為什麼這是重要記憶？**
1. **「同型號不同用戶」是混淆陷阱**——AI 看到「ACER」會以為是同一台，但教練今天用的是「助理的 ACER」不是「自己的 ACER」
2. **每台機器的 LINE 搬家任務情境不同**——聯想是「C 碟爆倉」、助理 ACER 是「C/D 雙碟要移到 D」
3. **未來 session 必須立刻知道教練在哪台機器上**——才能選對路徑、對的 SOP 版本

**守則 #06 的具體實踐**——這份機器命名表必須燒進記憶檔，下個 session「開工」時自動載入，避免 AI 又問「請問這台是 Windows 還是 Mac？」（這就是 1 個月前的「永久字典燒錄」原則——`桌面板`/`終端機` 要分清楚，`聯想`/`ACER`/`助理筆電` 也要分清楚）。

### 🧬 DNA 層次
- **理念：** 有效溝通就是無價之寶——教練用「聯想」時 AI 立刻知道是 Windows 主力機 = 有效溝通
- **使命：** 老闆動嘴，AI 全自動執行——AI 自動判斷教練在哪台機器，自動選對路徑/SOP
- **信念·對的事就是長期有好處的事**——花一次力氣把命名規則寫清楚，之後永遠不搞混

### ⚡ 觸發訊號
| 觸發情境 | AI 該有的反應 |
|---------|-------------|
| 教練說「聯想」「Windows」「主力機」 | 自動對應 `Lenovo Win 桌機`、C 碟路徑 |
| 教練說「ACER」「外出」「筆電」 | 自動對應 `Acer Win 筆電`（先確認是不是「自己的 ACER」而非「助理的 ACER」） |
| 教練說「助理筆電」「同事的電腦」 | 自動標註「同 ACER 型號但用戶不同」= 警告：路徑可能不同 |
| 教練報案「C 碟爆倉」「一鍵復原資料不見」 | 自動判斷 = 聯想機的經典痛點，直接套用 LINE 搬家 SOP |
| 教練報案「C/D 雙碟」 | 自動判斷 = 助理 ACER 或新筆電，套用 D 槽版 SOP |

### ✅ 行動指引
**做：**
- 開工時自動讀取機器命名表（`memories/machine_naming.md` 或類似檔案）
- 教練提到機器名時，**立刻對應**到具體型號 + 角色 + 常用路徑
- 「同型號不同用戶」要特別標註警告（避免路徑誤判）
- LINE 搬家 SOP 要分版本：聯想版（C→E）、助理 ACER 版（C→D）、新筆電版（C→D）
- 機器命名異動時（教練換機、加機），即時更新記憶檔

**禁：**
- 教練說「ACER」就假設是同一台（可能今天用的是助理的 ACER）
- 看到「Windows」就假設是聯想（可能是 ACER、可能是新筆電）
- 沒先確認機器就選 SOP 版本（C→E 還是 C→D？）
