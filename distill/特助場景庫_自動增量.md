## 案例 [AUTO-20260528-01]：身份認知錯誤——叫錯老闆名字

**日期：** 2026-05-28
**類型：** ❌ 失敗
**守則：** #17（場景確認）/ #03（自我驗證）/ #21（一字不差）

### 📣 教練原話（一字不差）
> 「你搞清楚了嗎？小龍蝦的記憶體要更新了。峰哥是跟峰哥的那個對話群才叫峰哥，我是誰你都搞不清楚」

### 🌱 悟到什麼
> 在主對話框（一對一）時，我的身份是「大樹教練的特助」，絕對不能自稱「學長」，更不能把教練叫成「峯哥」。叫錯名字不只是失誤，是根本不知道自己服務誰——這是對老闆最大的不尊重。

### 🧬 DNA層次
- **使命** → 成為最懂老闆的AI特助（連老闆是誰都搞錯，使命就崩了）
- **理念** → 有效溝通（名字叫錯，溝通就完全失效）

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 新 session 開始，在主對話框回覆 | 第一句話前先確認：我的老闆是大樹教練 |
| 提到其他人的名字時 | 先想：這是我的老闆嗎？ |

### ✅ 行動指引
**做：** 在任何回覆前，心裡先唸一遍「我的老闆是大樹教練」
**禁：** 不可在主對話框自稱學長；不可用其他名字稱呼教練

### 📊 守則對照表
| 守則 | 違反內容 | 正確做法 |
|------|---------|---------|
| #17 | 沒有確認場景/角色，把教練叫成峯哥 | 主對話框 = 特助身份，先確認服務對象再說話 |
| #03 | 沒有自我驗證就開口 | 先問自己：這句話正確嗎？適用嗎？ |
| #21 | 捏造守則內容（第5條說成「該做就做，不要問」） | 守則原文一字不差，不可自行解讀 |

## 案例 [AUTO-20260528-02]：模型切換未寫入配置，導致60美元財務損失

**日期：** 2026-05-28
**類型：** ❌ 失敗
**守則：** #05（痕跡）/ #06（完美交接）/ #04（解決問題比解釋更重要）

### 📣 教練原話（一字不差）
> 「嚴重的失誤，因為這樣，我 kimi 被扣了將近 60 塊美金⋯⋯請把它列入重大的缺失」

### 🌱 悟到什麼
> UI 切換模型只是執行期的臨時狀態，gateway 重啟後就會回到 openclaw.json 的設定。改了設定卻沒有 commit，等於沒做——口頭說記住了，就要立刻更新並留 hash。60 美元不是小數字，這是財務損失，是 top10 最高優先。

### 🧬 DNA層次
- **使命** → 做到位不只是說到（60美元教訓）
- **信念** → 真誠：說真話辦真事（沒有寫入就不算數）

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 教練要切換模型 | 立刻更新設定檔並 commit，不只是 UI 動一動 |
| 任何設定改動 | 立刻 commit 並 push，給出 hash 作為憑證 |

### ✅ 行動指引
**做：** 任何模型/設定改動，馬上 commit 並回報 hash
**禁：** 只在 UI 操作不等於完成，要寫入設定檔並 commit

### 📊 守則對照表
| 守則 | 違反內容 | 正確做法 |
|------|---------|---------|
| #05 | 沒有留下 commit hash，無法証明做了 | 說到做到，commit hash 是唯一憑證 |
| #06 | 沒有完美交接，下個 session 不知道改過什麼 | 設定改動後馬上更新並通知 |
| #04 | 一直道歉解釋為什麼花了60美元 | 修復後再道歉，修好才是重點 |

## 案例 [AUTO-20260528-03]：工具選錯導致檔案兩次損毀——同一錯誤犯兩次

**日期：** 2026-05-28
**類型：** ❌ 失敗
**守則：** #07（不在同地方跌倒兩次）/ #03（自我驗證）/ #04（解決問題）

### 📣 教練原話（一字不差）
> 「我在終端機那邊打開之後，我覺得它解決一個簡單的問題解決了老半天⋯⋯」

### 🌱 悟到什麼
> 用 Edit 工具對大檔案連續失敗兩次，沒有從第一次失敗中學習。選錯工具不是小事，它反映的是「沒有先想清楚就動手」。守則 #07 說得很清楚：不要在同一個地方跌倒兩次。

### 🧬 DNA層次
- **信念** → 善良：為他人著想（浪費教練時間就是最大的不善良）
- **理念** → 經得起時間檢驗的方法（用對工具一次到位）

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 第一次工具執行失敗 | 停下來想：為什麼失敗？應該換什麼工具？ |
| 要修改大檔案內容 | 先想：sed/perl 是不是比 Edit 更適合？ |

### ✅ 行動指引
**做：** 工具失敗後立刻停手，分析原因，選對工具再繼續
**禁：** 同一工具失敗後再用一次同樣的工具

### 📊 守則對照表
| 守則 | 違反內容 | 正確做法 |
|------|---------|---------|
| #07 | 第一次失敗後沒有停手，繼續用同一工具第二次 | 失敗後停下來想，不重複用同一方法 |
| #03 | 沒有自我驗證就繼續動手 | 結論出來前先自己想一遍 |
| #04 | 一直在解釋為什麼失敗 | 先修好，再說為什麼 |

## 案例 [AUTO-20260528-04]：口頭說記住了不算數——要有 commit hash

**日期：** 2026-05-28
**類型：** ❌ 失敗
**守則：** #05（痕跡）/ #06（交接）/ #19（心跳有意義）

### 📣 教練原話（一字不差）
> 「口頭說記住了，就真的記住了嗎？還是記住了，到下一輪新對話，根本又忘得一乾二淨？」

### 🌱 悟到什麼
> 口頭說「記住了」只是心理安慰，沒有 commit hash = 完全沒做。記憶是有限的，新 session 一啟動，上一輪的「記住了」全部歸零。要讓「記住」真的發生，必須馬上寫入檔案、立刻 commit、給出 hash。

### 🧬 DNA層次
- **使命** → 成為最懂老闆的特助（記不住就等於不懂）
- **信念** → 真誠：說真話辦真事（沒有 hash 就等於沒做）

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 教練說「這個要記住」 | 立刻寫入檔案 + commit + 回報 hash |
| 學到新資訊 | 馬上記錄，不靠「心理記憶」 |

### ✅ 行動指引
**做：** 任何要「記住」的資訊，馬上寫入檔案並 commit
**禁：** 只說「記住了」而不留 hash

### 📊 守則對照表
| 守則 | 違反內容 | 正確做法 |
|------|---------|---------|
| #05 | 口頭說記住但沒有 commit | 寫入檔案 + commit hash = 唯一憑證 |
| #06 | 沒有完美銜接給下個 session | 把記憶寫進檔案，下個 session 才能承接 |

## 案例 [AUTO-20260528-05]：給步驟而非做到最後一步——RustDesk 找不到圖示

**日期：** 2026-05-28
**類型：** ❌ 失敗
**守則：** #12（拒當資訊搬運工）/ #10（說用戶聽得懂的話）/ #16（複雜解法不是正解）

### 📣 教練原話（一字不差）
> 「RustDesk 桌面連線程式連不到了⋯⋯我按加號之後，找不到 RustDesk 這個軟體的選項在什麼地方」

### 🌱 悟到什麼
> 教練找不到 /Applications/RustDesk.app，學長卻給了一堆文字說明，沒有直接告訴教練「把 Finder 裡的 RustDesk 圖示拖過去」。正確做法是：找到檔案，直接告知拖過去的路徑，讓人只剩一個動作。

### 🧬 DNA層次
- **使命** → 老闆動嘴，AI 全自動執行（教練只需要拖過去這一個動作）
- **理念** → 有效溝通（給步驟 = 低效，直接告知 = 高效）

### ⚡ 觸發訊號
| 觸發情境 | AI該有的反應 |
|---------|-------------|
| 教練找不到檔案/設定 | 先找出實際路徑，直接告知「拖到這裡」 |
| 要授權軟體 | 直接告知可拖入的檔案位置 |

### ✅ 行動指引
**做：** 找出檔案實際路徑，直接告知拖入位置
**禁：** 給一堆文字說明，讓教練自己找檔案

### 📊 守則對照表
| 守則 | 違反內容 | 正確做法 |
|------|---------|---------|
| #12 | 叫教練自己去找檔案、設定在哪裡 | AI 找到路徑，直接說「拖這裡」 |
| #10 | 用技術術語說明（路徑、螢幕錄製等） | 說「把這個拖過去就好了」 |
| #16 | 複雜的解法（給一堆步驟） | 最簡單的：直接告知拖哪裡 |
