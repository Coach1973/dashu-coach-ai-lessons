## 12:45～13:05 修掉「榮樹下訪談提醒」重複排程（11/5、11/8 各有 5 個提醒 cron）

- **根因（兩個疊加）**：
  1. `sync_google()` 每次同步都重新產生 `gcal-<日期>-<序號>` 這種流水號 id，同一時間兩場互換位置時 id 就對調 → 舊 id 的提醒 cron 變成孤兒
  2. `rongshuxia_upcoming()` / `ensure_reminder()` 沒有濾掉「Google 日曆同步出來的鏡像事件」——同一場訪談在總表裡有正本（預約頁／巴哈）＋鏡像（Google日曆）兩筆，兩筆都被排了提醒
- **修法（commit `5eb5df644`，已推 origin/main）**：
  - 新增 `is_google_twin()`：來源是 Google日曆、且同時段有一筆非 Google 正本的榮樹下訪談 → 視為鏡像，不排提醒、不單獨推播
  - `ensure_reminder()`、`remind` 指令都擋鏡像；`rongshuxia_upcoming()` 直接不收鏡像
  - `sync_google()` 沿用舊事件 id 與 `reminder_job`，排序固定成 (日期, 開始, 標題, 結束) → id 不再跳
  - `guest_text()` 補從標題「榮樹下訪談：某某」讀名字 → 11/8 趙敏玄那場提醒不再沒名字（原本 guest 欄位空著）
  - 清掉 8 個重複／孤兒 cron，現存只剩 2 個：11/5→`7a14995c`（正本 05191591）、11/8→`ed4c40fd`（正本 d5a312f6）
- **驗證**：連續兩次 `sync-google` 後 326 筆 Google 事件 id 完全不動；`sync-reminders` 補排 0 個；提醒 job 總數 2；預約頁／LINE 演算法 466 個時段對照測試全部通過
