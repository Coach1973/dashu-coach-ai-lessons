## 🔴 二、bni_tainan 行事曆 `${time}` 髒資料 — 根因是解析器抓錯地方，不是資料壞掉 <!-- project: github.com/Coach1973/mac-openclaw-workflows -->

### 事實
- 症狀：`knowledge/tainan_calendar.md` 最後一筆「1219-1220(六日) M2（09:00-17:00，集思北科大，${time}）」多了 `${time}`。
- 根因：來源頁 `https://event.bymyway.com/tainan-calender/` 頁尾有「新增活動」用的 **JavaScript 模板程式碼**，裡面字面寫著 `<div class="meta-row"><span class="icon">🕒</span>${time}</div>`。解析器切完最後一筆活動的 event-item 區塊後，**尾端整段 `<script>` 被當成該活動的內容掃進去**，`${time}` 就被當成「時間」抓走。
- 修法（雙層）：① 解析前先 `re.sub(r"<script\b[^>]*>.*?</script>", "", html, flags=DOTALL|IGNORECASE)` 剝掉所有 script 區塊（活動資料本身是靜態 HTML，剝掉不影響）② 清洗 meta 時再擋一道任何 `${...}` 殘留。
- 驗證：重跑後 **106 筆一筆沒少**，逐行 diff 只有 2 行不同（同步時間戳 + 那筆的 `${time}` 消失），殘留模板變數 0。commit `8a97aff116fb39b656acc10dbbdb0085b6cfe6fc` 已推 `~/.openclaw` 的 **master**，local == remote。

### 🔴 教訓
1. **髒資料先問「髒在哪一層」**：上游資料壞掉 vs 自己的解析器壞掉，處置完全不同。先 `grep` 原始 HTML 找到那個字串**原本住在誰身上**，再決定改資料還是改程式。
2. **長頁面的 script/style 區塊一定要先剝掉再解析**，否則尾端 JS 模板會被當內容。這個通則不只適用行事曆。
3. `~/.openclaw` 是**獨立的 git repo（分支 master）**，`workspace/` 是另一個獨立 repo（分支 main），兩者 remote 相同但**分支不同**。`git_wrong_branch_guard.py` 就是在擋這個坑——`~/.openclaw` 推 master、`workspace` 推 main，不要混。
