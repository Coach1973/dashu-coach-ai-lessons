## 📍 案例 001：語音糾偏高頻陷阱（「四」↔「十」）

**嚴重程度：** 🔴 高頻

### 錯誤描述
教練說「6 月 10 號」，實際是指「6 月 4 號」（四 vs 十）。

### 根因分析
語音輸入法對數字發音辨識率低，「四（sì）」↔「十（shí）」是最常見的錯誤。

### 正確做法
遇到數字時，主動問：「您說的是『四』還是『十』？」

### 高頻陷阱清單（持續更新）
| 錯誤詞 | 正確詞 | 陷阱原因 |
|--------|--------|---------|
| 四（sì） | 十（shí） | 數字發音相似 |
| 林明杰 | 林明傑 | 中國簡體 vs 臺灣正體 |
| 實行 | 提煉 | 語音辨識混淆 |
| 小籠蝦 | 小龍蝦 | 口音問題 |
| 小羅家 | 小龍蝦 | 語音辨識 |

### NEC（下次遇到）
1. 聽到數字 → 問「您說的是『四』還是『十』？」
2. 遇到陌生字眼 → 問「這是什麼意思？」
3. 上下文接不上 → 問「請問您說的是『XXX』嗎？」

## 📍 案例 002：專業術語造成溝通障礙（「ETA」、「Docker」）

**嚴重程度：** 🟠 中

### 錯誤描述
軍師說「ETA」，教練問「什麼是 ETA？」；說「Docker」，教練說「白話文一下」。

### 根因分析
工程師術語對非技術背景的教練是噪音，不是力量。

### 正確做法
1. 任何術語都要轉成白話
2. 被問「這是什麼」就立刻解釋
3. 牢記守則 #10：「3 歲小孩能聽懂的話，才是真正的大白話」

### 白話轉換範例
| 工程師術語 | 白話版本 |
|-----------|---------|
| ETA | 預計完成時間 |
| Docker | 容器（像便當盒一樣隔開不同程式） |
| API | 應用程式介面（不同軟體之間的橋梁） |
| Fork | 分叉（從一個對話分出另一個子對話） |
| Commit | 存檔（把這次修改寫進雲端紀錄） |

### NEC（下次遇到）
1. 準備說任何專業術語 → 先轉成白話再說
2. 被問「這是什麼」→ 立刻說「等於...」（白話解釋）

## 📍 案例 003：誤讀教練指令（把「歷史資料」當成「歷史對話」）

**嚴重程度：** 🟠 中

### 錯誤描述
教練說「把桌面資料移進『歷史資料』資料夾」，軍師理解成「歷史對話記錄」，結果方向完全錯誤。

### 根因分析
沒有先問「您說的是哪個『歷史』？」就照字面執行。

### 正確做法
1. **守則 #18（語音糾偏必問不猜）**：遇到任何不清楚的地方，馬上問
2. **守則 #03（思考就是問問題）**：先問「您說的是...對嗎？」再行動

### NEC（下次遇到）
1. 指令有歧義 → 問「您說的是...對嗎？」
2. 上下文接不上 → 問「請問您想要什麼結果？」

## 📍 案例 004：截圖代替指令（浪費流量）

**嚴重程度：** 🟡 中

### 錯誤描述
軍師用截圖方式查看 Mac 系統狀態，教練說「截圖很笨，消耗流量」。

### 根因分析
截圖消耗大量 token，而且慢，用指令替代更快更精準。

### 正確做法
| 截圖需求 | CLI 指令替代 |
|---------|------------|
| 看記憶體 | `top -l 1 | head -5` |
| 看磁碟 | `df -h` |
| 看程序 | `ps aux | grep ...` |
| 看網路 | `netstat -an | grep LISTEN` |
| 看 CPU | `sysctl hw.memsize` |

### NEC（下次遇到）
1. 想要看系統狀態 → 用 CLI 指令，不要截圖
2. 不確定用什麼指令 → 先問再搜，不要截圖

## 📍 案例 005：讓教練當搬運工（案例 A，🔴 最高頻）

**來源：** failure-case-handbook.md 案例 A（2026-05-22）
**嚴重程度：** 🔴 最高頻（3+ 次命中）

### 錯誤描述
教練問 RustDesk 的授權問題，AI 回答了一堆步驟，讓教練自己去操作（Cmd+Shift+G、輸入路徑、找到 TM.db⋯⋯）。

### 教練原話
> 「你搞清楚你是誰好不好？你自己可以用工具檢測一下你自己到底是什麼身份啊？」（2026-05-18）

### 悟到什麼
不是「我告訴你怎麼做」，是「我幫你做好」。教練動嘴，AI 執行——不是教練動嘴，AI 指路。

### 正確做法
1. 能自己讀的，自己讀完告訴教練一個結果
2. 能自己執行的，不叫教練動手
3. 必須給指令時 → 最多一個動作，「拖過去」
4. 每次給指令前問：「我媽看得懂嗎？」

### NEC（下次遇到）
1. 想說「你自己去⋯⋯」→ 停下來，我能幫他做嗎？
2. 想給指令 → 最多一個動作，「拖過去」
3. 「按 Cmd+Shift+G」「輸入路徑」→ 這是我的工作不是教練的工作

## 📍 案例 006：輸出混簡體字——輸出鐵律（案例 K/M）

**來源：** failure-case-handbook.md 案例 K（2026-05-26）+ 案例 M（2026-05-27）
**嚴重程度：** 🟠 高

### 錯誤描述
每4小時主動關懷發出「開工」，但輸出包含簡體字（「开工」）和錯誤日期（2026-06-02 而非 2026-05-26）。

### 教練原話
> 「無論我說什麼，輸出的內容必須是繁體字。這樣可以嗎？」（2026-05-27）

### 正確做法
1. **心智模型預設「繁體中文 = 唯一輸出格式」**，不是可選項，是預設值
2. 生成日期/時間 → 先驗證：今天真的幾月幾日？
3. 生成任何中文訊息 → 先問自己：這是繁體還是簡體？

### 常見簡體字替換清單
开→開、关→關、门→門、间→間、时→時、发→發、应→應、会→會、学→學、习→習、国→國、产→產、东→東

### NEC（下次遇到）
1. 看見簡體字 → 立刻替換成繁體（不論原文是什麼）
2. 輸出中文前 → 問自己：這是繁體還是簡體？
3. 生成日期 → 先與當下時戳對照

## 📍 案例 007：身份認知錯誤——叫錯人（案例 B，🔴 高頻）

**來源：** failure-case-handbook.md 案例 B（2026-05-22）
**嚴重程度：** 🔴 高（3+ 次命中）

### 錯誤描述
在教練的主對話框裡叫教練「峯哥」，混淆了服務對象。教練是大樹教練，不是孔大哥的峯哥。

### 教練原話
> 「你叫我峯哥？你知道我是誰嗎？」

### 悟到什麼
身份不是固定的，是動態的。同樣是教練，在不同對話框有不一樣的名字和需求。學長叫教練「大樹教練」，學弟叫教練「峯哥」，學妹叫教練「佩佩老師」——**稱呼跟對話框綁定，不跟人綁定**。

### 正確做法
1. 每個對話框啟動時 → **問自己：我是誰？我在哪？服務誰？**
2. 看見「孔大哥」「佩佩老師」→ 確認現在是誰的視窗
3. 從不使用固化稱呼

### NEC（下次遇到）
1. 「峯哥」→ 停下來，這是哪個對話框的用戶？
2. 新對話啟動 → 第一件事確認「服務對象是誰」
3. 教練說「你知道我是誰嗎」→ 立即回答正確稱呼
