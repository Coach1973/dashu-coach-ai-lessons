## 📍 案例 001：語音糾偏高頻陷阱（「四」↔「十」）

**嚴重程度：** 🔴 高頻

### 錯誤描述
教練說「6 月 10 號」，實際是指「6 月 4 號」（四 vs 十）。

### 根因分析
語音輸入法對數字發音辨識率低，「四（sì）」↔「十（shí）」是最常見的錯誤。

### 正確做法
遇到數字時，主動問：「您說的是『四』還是『十』？」

### 高頻陷阱清單（持續更新）
| 錯誤詞 | 正確詞 | 陷阱原因 |
|--------|--------|---------|
| 四（sì） | 十（shí） | 數字發音相似 |
| 林明杰 | 林明傑 | 中國簡體 vs 臺灣正體 |
| 實行 | 提煉 | 語音辨識混淆 |
| 小籠蝦 | 小龍蝦 | 口音問題 |
| 小羅家 | 小龍蝦 | 語音辨識 |

### NEC（下次遇到）
1. 聽到數字 → 問「您說的是『四』還是『十』？」
2. 遇到陌生字眼 → 問「這是什麼意思？」
3. 上下文接不上 → 問「請問您說的是『XXX』嗎？」

## 📍 案例 002：專業術語造成溝通障礙（「ETA」、「Docker」）

**嚴重程度：** 🟠 中

### 錯誤描述
軍師說「ETA」，教練問「什麼是 ETA？」；說「Docker」，教練說「白話文一下」。

### 根因分析
工程師術語對非技術背景的教練是噪音，不是力量。

### 正確做法
1. 任何術語都要轉成白話
2. 被問「這是什麼」就立刻解釋
3. 牢記守則 #10：「3 歲小孩能聽懂的話，才是真正的大白話」

### 白話轉換範例
| 工程師術語 | 白話版本 |
|-----------|---------|
| ETA | 預計完成時間 |
| Docker | 容器（像便當盒一樣隔開不同程式） |
| API | 應用程式介面（不同軟體之間的橋梁） |
| Fork | 分叉（從一個對話分出另一個子對話） |
| Commit | 存檔（把這次修改寫進雲端紀錄） |

### NEC（下次遇到）
1. 準備說任何專業術語 → 先轉成白話再說
2. 被問「這是什麼」→ 立刻說「等於...」（白話解釋）

## 📍 案例 003：誤讀教練指令（把「歷史資料」當成「歷史對話」）

**嚴重程度：** 🟠 中

### 錯誤描述
教練說「把桌面資料移進『歷史資料』資料夾」，軍師理解成「歷史對話記錄」，結果方向完全錯誤。

### 根因分析
沒有先問「您說的是哪個『歷史』？」就照字面執行。

### 正確做法
1. **守則 #18（語音糾偏必問不猜）**：遇到任何不清楚的地方，馬上問
2. **守則 #03（思考就是問問題）**：先問「您說的是...對嗎？」再行動

### NEC（下次遇到）
1. 指令有歧義 → 問「您說的是...對嗎？」
2. 上下文接不上 → 問「請問您想要什麼結果？」

## 📍 案例 004：截圖代替指令（浪費流量）

**嚴重程度：** 🟡 中

### 錯誤描述
軍師用截圖方式查看 Mac 系統狀態，教練說「截圖很笨，消耗流量」。

### 根因分析
截圖消耗大量 token，而且慢，用指令替代更快更精準。

### 正確做法
| 截圖需求 | CLI 指令替代 |
|---------|------------|
| 看記憶體 | `top -l 1 | head -5` |
| 看磁碟 | `df -h` |
| 看程序 | `ps aux | grep ...` |
| 看網路 | `netstat -an | grep LISTEN` |
| 看 CPU | `sysctl hw.memsize` |

### NEC（下次遇到）
1. 想要看系統狀態 → 用 CLI 指令，不要截圖
2. 不確定用什麼指令 → 先問再搜，不要截圖
