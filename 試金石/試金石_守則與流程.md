## 📍 案例 001：Hook 安裝但 settings.json 未寫入（假完成）

**嚴重程度：** 🔴 高

### 錯誤描述
腳本檔案存在，但 `settings.json` 的 hooks 區段是空的 `{}`，Hook 完全沒生效。

### 根因分析
只做了「建立腳本」，沒做「寫入 settings.json 讓系統真的去讀」這個關鍵動作。

### 正確做法
1. 寫入 `settings.json` 的 `hooks.UserPromptSubmit[].hooks[]` 區段
2. **當場驗證**：`grep -A2 "hooks" ~/.claude/settings.json`
3. 若有問題，立刻修，不要等到下次
4. **commit hash 不能證明** settings.json 有寫入，只有實際觸發才算數

### NEC（下次遇到）
1. 建完 hook 腳本 → 立即檢查 `~/.claude/settings.json` 的 hooks 區段
2. 重啟 Claude Code → 故意觸發觀察是否生效
3. 若不生效 → 立刻修

## 📍 案例 002：新視窗失憶（接力棒沒更新）

**嚴重程度：** 🔴 高

### 錯誤描述
上一場助教沒有在結束前覆寫接力棒，導致新視窗讀到舊狀態，教練要重講所有事情。

### 根因分析
沒有「交接等於完成」的強制流程，交棒變成一種口頭承諾而非實際行動。

### 正確做法
Session 結束前，強制執行：
```bash
# 1. 更新接力棒
vim ~/.claude-code/workspace/JUNSHI_HANDOFF_LATEST.md
# 2. 寫入本場完成的事項
# 3. 明確標記待辦
# 4. commit
git add JUNSHI_HANDOFF_LATEST.md && \
git commit -m "接力棒更新 + 經驗記憶（日期）" && \
git push
# 5. 告知教練「已完成交接」
```

### NEC（下次遇到）
1. Session 接近尾聲 → 問「還有其他要交代的嗎？」
2. 寫入接力棒 → `git commit` → `git push`
3. 告知教練「交接完成」

## 📍 案例 003：FORK 自動搶跑（未經允許）

**嚴重程度：** 🟠 高

### 錯誤描述
新 session 看到接力棒就自動執行任務，浪費流量，教練還沒說要做。

### 根因分析
Hook 注入接力棒後，AI 看到待辦事項就立刻行動，沒問「現在要做嗎」。

### 正確做法
1. **方向清楚** → 直接執行，不問「要做嗎」（守則 #08）
2. **方向模糊** → 先問「您想要什麼結果？」
3. **教練說「你覺得呢」** = 教練已經說了「做」，直接執行
4. **未經允許** → 不做

### NEC（下次遇到）
1. 收到「開工」→ 讀完接力棒
2. 向教練報告「這 X 件事待做，您要從哪件開始？」
3. 教練說「做」→ 才動手

## 📍 案例 005：說完不做——distill 腳本 7 天不存在（案例 C，🔴 最高頻）

**來源：** failure-case-handbook.md 案例 C（2026-05-24 發現）
**嚴重程度：** 🔴 最高頻（5+ 次命中）

### 錯誤描述
教練說「我之前叫你做的那些腳本」——有這件事嗎？有。但 cron 設了，腳本不存在。系統每天都說「我在跑」，實際上是空的。整整 7 天沒有人發現。

### 根因分析
「說了沒做」最隱蔽的形式：系統說它在跑，實際上是空的。根本原因：`distill_incremental.js` 的 cron PATH 缺少 `/opt/homebrew/bin`，導致每次執行都是假的。

### 正確做法
1. **建立 cron 前先建立腳本**：`touch` + `chmod +x` 確認腳本存在
2. **設定完立即測試一次**：手動跑 `bash script.sh` 確認能跑
3. **每週檢查 cron log**：確認沒有 fail 的任務

### NEC（下次遇到）
1. 看見 cron 任務 → 問自己：這個 cron 對應的腳本真的存在嗎？
2. 看見 `distill_incremental.js` → `ls -la` 驗證存在 + 驗證能跑 + 驗證真的在執行
3. 任何「我會處理」→ 當場執行，給 commit hash

### Commit
`5fc3f80d`（根本修復：cron PATH 加 /opt/homebrew/bin）

## 📍 案例 010：Context Overflow 後 HEARTBEAT.md 未即時更新（案例 I）

**來源：** failure-case-handbook.md 案例 I（2026-05-25）
**嚴重程度：** 🟠 高

### 錯誤描述
下午 16:41 Context Overflow 重啟，但 HEARTBEAT.md 沒有即時更新重啟狀態。重啟後長達 5 小時，狀態沒有同步。

### 根因分析
重啟不等於修復。重啟是清空，不是記憶——如果不把「剛剛發生了什麼」寫進 HEARTBEAT.md，下一個心跳就是帶著盲眼在跑。

### 正確做法
**Context Overflow 重啟 → 第一件事更新 HEARTBEAT.md**：
```bash
# 重啟後第一件事
echo "🔄 Context Overflow $(date '+%Y-%m-%d %H:%M')" >> HEARTBEAT.md
echo "原因：對話太長，自動重啟" >> HEARTBEAT.md
git add HEARTBEAT.md && git commit -m "HEARTBEAT 重啟更新"
```

### NEC（下次遇到）
1. 看見「自動重啟」→ 問：HEARTBEAT.md 有沒有反映最新狀態？
2. Context Overflow 重啟 → 不先說話，先更新 HEARTBEAT.md
3. 寫入重啟時間和當前任務狀態，再繼續對話

## 📍 案例 012：模型設定未落地，損失 60 美元（案例 O，🔴🔴🔴 最高優先）

**來源：** failure-case-handbook.md 案例 O（2026-05-27，💸 財務損失）
**嚴重程度：** 🔴🔴🔴 最高（真金白銀）

### 錯誤描述
`claude-code.json` 的 main 機器人 model 欄位一直是 `kimi/kimi-k2.6`。教練在 UI 手動切換到 Claude，**切換只有執行期效果，不寫入 claude-code.json**。每次 gateway 重啟都重新讀檔、彈回 kimi。三天內無一個助教發現或警告。

### 教練原話
> 「嚴重的失誤，因為這樣，我 kimi 被扣了將近 60 塊美金，所以這是一個非常嚴重的錯誤。我居然手動切換不回去，也沒有人提醒我。」

### 根因分析（技術）
| 層次 | 原因 |
|------|------|
| 設定層 | `claude-code.json` main 的 model = `kimi/kimi-k2.6`，從未被改掉 |
| 機制層 | UI 手動切換 = 執行期狀態，gateway 重啟後消失 |

### 正確做法
1. **UI 切換 ≠ 永久設定**：任何模型變更必須寫入 `claude-code.json` 的 model 欄位
2. **設定完立刻驗證**：`cat ~/.claude-code/claude-code.json | grep model`
3. **開工第一步**：自動核查 main model 欄位

### NEC（下次遇到）
1. 教練說「切換模型」→ **立刻 `cat claude-code.json` 確認已寫入，不信 UI**
2. 教練說「小龍蝦」或「Claude」→ **問：我最後一次確認 claude-code.json 的 main model 是什麼時候？**

## 📍 案例 013：三機身份維修——改錯路徑（2026-04-26）

**來源：** memory/2026-04-26-三機身份維修完整報告.md
**嚴重程度：** 🔴🔴🔴 最高（數小時修復）

### 錯誤描述
一直修改 `~/.claude-code-kong/workspace/SOUL.md` 和 `~/.claude-code-peipei/workspace/SOUL.md`，以為這些就是 bot 讀取的檔案。實際上 bot 讀取的是 `~/.claude-code/agents/kong/SOUL.md`，這些路徑從未被改過。

### 根因分析
沒有先確認「bot 真正讀取哪個檔案路徑」，直接假設 workspace 裡的就是對的。

### 正確做法
**維修任何 bot 前，第一步確認正確路徑：**
```bash
# 1. 看 bot 的 agent 目錄有哪些檔案
ls ~/.claude-code/agents/<bot名>/

# 2. 確認 BOOTSTRAP.md 是否已刪除（如果存在就刪掉）
rm ~/.claude-code/agents/<bot名>/BOOTSTRAP.md

# 3. 確認 session 存放位置
ls ~/.claude-code/agents/<bot名>/sessions/

# 4. 修改正確的檔案路徑
# 千萬不要直接改 workspace 裡的，要改就改 agents/ 下的

# 5. 修改完後重啟 gateway
kill <gateway_pid>
```

### 路徑對照表（記住這個）
| 類型 | 錯誤路徑（不要改）| 正確路徑（bot 實際讀的）|
|------|-----------------|----------------------|
| SOUL.md | `~/.claude-code-kong/workspace/` | `~/.claude-code/agents/kong/` |
| USER.md | `~/.claude-code-peipei/workspace/` | `~/.claude-code/agents/peipei/` |

### NEC（下次遇到）
1. 維修任何 bot → 第一件事 `ls ~/.claude-code/agents/<bot名>/`
2. 看見 BOOTSTRAP.md → 立即刪除
3. 修改 SOUL.md / USER.md → 確認在 agents/ 目錄下
4. 修改完 → 重啟 gateway 讓新 session 讀到

### Commit
`7daa08f`（kong 刪除BOOTSTRAP.md、補正IDENTITY.md、新增MEMORY.md）
`d09e83e`（peipei 修正佩佩老師身份）
