## 📍 案例 001：模型切換失效（$60 美元財務損失）

**嚴重程度：** 🔴 最高優先

### 錯誤描述
教練在 UI 上手動切換到 Claude，看起來成功了，但兩天後系統仍在跑 Kimi，被扣了近 $60 美金。

### 根因分析
- UI 切換是「執行期臨時狀態」，每次 gateway 重啟都重新讀 `claude-code.json`
- `claude-code.json` 裡 `main` agent 的 model 欄位從未改過（還是 `kimi/kimi-k2.6`）
- 三台機器（三個 Bot）各自獨立設定，都需要改

### 正確做法
1. **改 UI** — 臨時生效
2. **檢查 `claude-code.json`** — 看 model 欄位是否真的寫入：`grep -A2 '"model"' ~/.claude-code/claude-code.json`
3. **若沒變** — 直接 vim 改 `model` 欄位從 `kimi/kimi-k2.6` 改為 `claude/Claude Opus`
4. **重啟 gateway** — `claude-code restart` 或 kill 後重啟
5. **驗證** — 看 `ps aux | grep claude-code` pid 是否換了（新設定生效）

### 預防措施
每次切換模型後，順手執行：`grep '"model"' ~/.claude-code/claude-code.json | head -5`

### NEC（下次遇到）
1. 教練說「我切了但沒效」→ 先問「有沒有重啟 gateway？」
2. `grep '"model"' ~/.claude-code/claude-code.json` 看設定值
3. 若仍是舊值，手動改 `claude-code.json`，重啟
4. 驗證後回報，並告知 commit hash

## 📍 案例 002：`/model` 選單不出現目標模型

**嚴重程度：** 🟠 高

### 錯誤描述
教練想選 M3，但 `/model` 選單只有 22 個模型，沒有 Claude Opus。

### 根因分析
`/model` 選單讀的是 `claude-code.json` 的 `models.providers.claude.models[]`，M3 沒有列冊。

### 正確做法
1. 找到 `models.providers.claude.models` 區段
2. 補上 M3 進列表
3. 重啟 Claude Code gateway
4. `/model` 就能看到 M3 了

### NEC（下次遇到）
1. 模型已安裝但 `/model` 選單沒有 → 檢查 `models.providers.*.models[]`
2. 補上後重啟 gateway
3. commit hash：`1df3b9c`

## 📍 案例 003：Lumen/Proxy 殘留設定（OpenCode 無法連線）

**嚴重程度：** 🟠 高

### 錯誤描述
移除 Lumen 後，OpenCode 終端機和 UI 都無法連線，瀏覽器出現 `ERR_PROXY_CONNECTION_FAILED`。

### 根因分析
Lumen 移除時 HTTP/HTTPS/SOCKS 三個 Proxy 設定沒清乾淨，加上 `opencode.jsonc` 的 `baseURL` 仍指向 `127.0.0.1:9090`（Lumen 代理位址）。

### 正確做法
1. **系統 Proxy 全禁**：`System Preferences → Network → Proxy → 全部 Disable`
2. **`opencode.jsonc` 回歸直連**：`baseURL` 改回 `https://opencode.ai/zen/go/v1`
3. **重啟 OpenCode UI**

### 預防措施
安裝 Lumen 或任何 Proxy 工具前，先想好移除時要清哪些設定。

### NEC（下次遇到）
1. 「網頁不動」→ 先查 Proxy 設定
2. OpenCode 連不上 → 檢查 `ANTHROPIC_BASE_URL` 環境變數 + `opencode.jsonc` 的 baseURL
3. 不要輕易裝 Lumen，代價太大
