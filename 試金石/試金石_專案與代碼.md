## 📍 案例 003：watchdog 假回報（說了等於做到是假的）

**嚴重程度：** 🟠 高

### 錯誤描述
log 顯示 osascript 因為 macOS 權限被拒，但腳本仍然寫「✅ 已送出繼續指令」成功訊息。

### 根因分析
腳本沒有檢查 exit code，失敗了還說成功——等於在撒謊。

### 正確做法
```bash
# 抓 exit code + stderr
osascript -e 'tell application "System Events" to...' 2>&1
exit_code=$?

if [ $exit_code -ne 0 ]; then
    echo "❌ osascript 權限被拒"
    # 錯誤訊息寫進 log
else
    echo "✅ 繼續指令已送出"
fi

# 去重：24 小時內同樣錯誤只寫一次
# 連續失敗 3 次以上 → 寫進 HEARTBEAT.md
```

### NEC（下次遇到）
1. 任何腳本的成功訊息 → 要檢查 exit code
2. 失敗寫 ❌，成功寫 ✅，不要都寫 ✅

## 📍 案例 004：feed_junshi_handoff.sh 從未進 git（檔案消失）

**嚴重程度：** 🟡 中

### 錯誤描述
Hook 腳本 `feed_junshi_handoff.sh` 不見了，settings.json 指向它卻讀不到。

### 根因分析
腳本建立了，commit 了，但 commit 的是整個目錄的快照，檔案沒有真的進 repo（可能是 `.gitignore` 問題）。

### 正確做法
1. **建立檔案後立即 commit**：`git add 檔案 && git commit -m "新增 hook 腳本"`
2. **驗證**：建立後立刻讀回來，確認真的有進 repo
3. **用 git log 確認**：`git log --oneline -- 檔案路徑`

### NEC（下次遇到）
1. 建立任何重要腳本 → 立刻 commit
2. commit 後 → `git log -- 檔案路徑` 確認進了 repo
3. 失敗從 git 歷史恢復：`git checkout <commit-hash> -- 檔案`
