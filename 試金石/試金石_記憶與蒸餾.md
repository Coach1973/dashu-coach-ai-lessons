## 📍 案例 001：distill_vps.py 蒸餾後沒有 push

**嚴重程度：** 🟠 高

### 錯誤描述
蒸餾腳本執行完後，結果留在本地，沒有同步上雲。

### 根因分析
腳本寫完後沒有接 `git add && git commit && git push`。

### 正確做法
每次蒸餾後：
```bash
# 1. 寫入 pending_distill
cp result.md pending_distill/

# 2. 處理完後 commit + push
git add distill/ && \
git commit -m "蒸餾：$DATE + 摘要" && \
git push
```

### NEC（下次遇到）
1. 蒸餾腳本執行完 → 檢查 `git status`
2. 若有未 commit 的蒸餾結果 → 立刻 commit + push

## 📍 案例 002：蒸餾流程（extract → distill → push）

**嚴重程度：** 🟡 中

### 完整流程
```
1. extract_terminal_sessions.py
   → pending_distill/（原始對話 raw）

2. distill_terminal_llm.py（Claude API）
   → distill/terminal_YYYY-MM-DD.md（蒸餾後）

```

### 正確做法
- 每一步都要有檢查點
- 不要跳過任何步驟
- commit hash 是唯一憑證

## 📍 案例 003： память 系統（接力棒 vs HEARTBEAT vs memory）

**嚴重程度：** 🟡 中

### 三層架構

## 📍 案例 004：commit hash 是唯一憑證

**嚴重程度：** 🔴 最高

### 核心原則
- 口頭說「完成了」不算
- 只有 commit hash 能證明「做過了」
- 每次交付都要有 hash

### 正確做法
```bash
# 每次完成後
git add . && git commit -m "說明" && git push
# 回報時一定要給 hash
```

### NEC（下次遇到）
1. 教練說「完成了」→ 立刻 commit + 給 hash
2. 沒給 hash = 沒做
