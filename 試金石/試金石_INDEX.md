> 創建日期：2026-06-03
> 最後更新：2026-06-03

---

## 📋 核心原則

**試金石的價值在於：「這個錯誤我犯過，下次不再犯。」**

每一筆記錄包含：
- **錯誤描述**：出了什麼問題
- **根因分析**：為什麼會犯
- **正確做法**：現在怎麼做才對
- **預防措施**：未來如何避免
- **NEC（Never Again Checklist）**：下次遇到同類場景立刻做的檢查清單

### 第一名：Netlify 部署鐵律（已 SOP 化）

| 項目 | 內容 |
|------|------|
| **錯誤** | 未經教練確認就推送、連續推修小問題、浪費 Netlify 部署次數 |

| **NEC** | ① 本機 `/tmp/` 建檔 → ② open 瀏覽器預覽 → ③ 教練說「推」→ ④ zip + curl 一次性上傳 |
| **Commit** | `d3978d2f`（SOP 定稿） |

### 第二名：鼠鬚管輸入法修復 SOP

| 項目 | 內容 |
|------|------|
| **錯誤** | 每次打開 Squirrel.app 都會重複註冊輸入源，導致 ABC 出現 4 個鼠鬚管 |
| **根因** | macOS 不會自動刪除舊的輸入源，每次部署都疊加 |
| **正確做法** | 1. 系統設定手動刪除多餘的 → 2. 備份 `~/Library/Rime` → 3. 清理 `build/*.bin` → 4. 重新部署 → 5. 驗證只有 1 個 |
| **預防** | 不要頻繁打開 Squirrel.app 部署，平常用 `Ctrl+Space` 切換即可 |
| **NEC** | ① `cp -r ~/Library/Rime ~/Library/Rime/_backup_$(date +%Y%m%d_%H%M%S)` → ② `rm -rf ~/Library/Rime/build/*` → ③ `open -a Squirrel` → ④ 等 10 秒確認 `.bin` 生成 → ⑤ 檢查 `defaults read HIToolbox.plist` 只有 1 個 Squirrel |
| **Commit** | `f2448c85` |

### 第三名：HTML 預覽不走 localhost（錯誤地圖陷阱）

| 項目 | 內容 |
|------|------|
| **錯誤** | 軍師端 Chrome MCP 看不到 Mac localhost，以為 HTML 有問題 |
| **根因** | 軍師的 Chrome MCP 連的是教練 Windows 機，不是 Mac 本機 |
| **正確做法** | HTML 預覽走 GitHub Pages（`coach1973.github.io/`），不走 localhost |
| **預防** | 遇到 HTML 預覽問題，先確認自己的 MCP 指向哪台機器 |
| **NEC** | ① 確定 MCP 指向的機器 → ② 走 GitHub Pages 或 `python3 -m http.server` 讓教練自己開 → ③ 不要假設自己能從瀏覽器看到 Mac localhost |

### 第四名：模型切換失效（$60 美元財務損失）

| 項目 | 內容 |
|------|------|
| **錯誤** | UI 手動切換模型看起來成功，但 gateway 重啟後就回到舊設定 |
| **根因** | UI 切換是「執行期臨時狀態」，不會寫入 `claude-code.json`；`main` agent 的 model 欄位從未改過 |
| **正確做法** | 必須直接修改 `claude-code.json` 裡的 model 欄位，然後重啟 gateway |
| **預防** | 每次切換模型後，順手檢查 `claude-code.json` 的 model 欄位是否真的變了 |
| **NEC** | ① 改 UI → ② 檢查 `~/.claude-code/claude-code.json` 的 `agents.*.model` → ③ 若沒變，手動改 → ④ `claude-code restart` → ⑤ 驗證 `ps aux | grep claude-code` 的 pid 是否換了 |

### 第五名：plists 操作高危險（plistlib.dump 簽名搞反）

| 項目 | 內容 |
|------|------|
| **錯誤** | Python `plistlib.dump` 用錯簽名，導致 `HIToolbox.plist` 變成 0 byte |
| **根因** | 簽名格式寫反，導致檔案被覆蓋成空白 |
| **正確做法** | 任何寫入 plist 前，先 `cp` 備份；寫入後立即 `defaults read` 驗證 |
| **預防** | 寫入後立即讀取驗證，發現問題立刻重建 |
| **NEC** | ① `cp ~/Library/Preferences/com.apple.HIToolbox.plist ~/Library/Preferences/com.apple.HIToolbox.plist.bak` → ② 寫入 → ③ `defaults read ~/Library/Preferences/com.apple.HIToolbox.plist | grep Squirrel` → ④ 若失效立刻還原 `cp *.bak *.plist` |

### 第七名：Hook 安裝但 settings.json 未寫入（假完成）

| 項目 | 內容 |
|------|------|
| **錯誤** | 腳本檔案存在，但 `settings.json` 的 hooks 區段是空的 `{}` |
| **根因** | 只做了「建立腳本」，沒做「寫入 settings.json」這個關鍵動作 |
| **正確做法** | 每個 Hook 安裝後，都要當場驗證能觸發 |
| **預防** | commit hash 不能證明 settings.json 有寫入，只有實際觸發才算數 |
| **NEC** | ① 寫入 `settings.json` → ② 重啟 Claude Code → ③ 故意觸發觀察是否生效 → ④ 失敗立刻修 |

### 第八名：語音糾偏高頻陷阱

| 項目 | 內容 |
|------|------|
| **錯誤** | 「四（sì）」↔「十（shí）」、「林明杰」↔「林明傑」、「實行」↔「提煉」 |
| **根因** | 語音輸入法辨識率問題，教練說的跟實際意思不同 |

| **預防** | 把高頻陷阱記下來，下次遇到同類情況自動警覺 |
| **NEC** | ① 陌生字眼 → ② 主動問「這是什麼？」→ ③ 確認後再行動 |
